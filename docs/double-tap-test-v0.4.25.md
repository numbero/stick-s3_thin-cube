# 双敲测试与诊断：Mac v0.4.25

历史记录：v0.4.26 已按用户要求移除本页所述的主动测试、窗口键盘捕获及回读验证，改为自动记录事件的[按键诊断](key-diagnostics-v0.4.26.md)。以下保留 v0.4.25 的实现与验收记录。

入口：「按键 → 测试与诊断…」。沿用 A/B 的权限显示、窗口测试和事件日志，新增双敲快捷键测试及完整系统回读验证。设备仍为 v0.4.56；识别算法、参数和映射不变，双甩保持移除。

## 本地快捷键测试

「测试双敲快捷键」读取当前设备已保存的双敲绑定，自动开始本窗口测试，向 ThinCube 自身发送一次完整的按下与松开。不需要做敲击动作，也不要求设备在线。未设置绑定、权限不足、编辑快捷键或升级期间按钮禁用。

只有系统在 2 秒内回读全部预期事件，且键码、按下/松开顺序及修饰键侧别均一致，才显示「双敲验证通过」。缺少松开、错误按键、顺序或修饰键不符会失败；窗口失焦、Esc、停止测试或关闭窗口会取消尚未完成的验证。每次双敲测试使用独立来源标记，物理键盘、普通设备事件和上次延迟到达的回读均不能替代本次验证。

这验证的是配置与键盘注入，不代表物理双敲识别率已通过。若组合中的修饰键已全部被物理键盘保持而没有提交新事件，则不会宣称通过。

## 设备双敲验证

保持倒置传音、A/B 松开，手持实验模式关闭。点击「开始本窗口测试」，在设备做一次双敲。页面显示当前绑定、固件支持与协议协商状态；日志保留设备事件序号和年龄、未注入的原因、提交的按下/松开及系统回读结果。监测期间设备双敲也发往 ThinCube 自身并执行同样的完整回读验证。

停止窗口测试后恢复正常双敲发送路径。识别参数的调整仍使用独立参数页；自动采样工具保持原样，不重新引入手动试次、标注或导出流程。
