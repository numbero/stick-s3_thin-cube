# 电量显示与短时耗尽排查

日期：2026-10-13。核查代码为仓库 `60130b6`，真机读取版本为 `v0.4.14`。本轮完成源码检查、官方资料核查、算法回放、现有测试和 USB 基线采集；没有修改运行代码、烧录固件或重建 macOS 应用。

后续用户授权直接调试后，已实施并安装 v0.4.15 显示跟踪修复与 Mac 0.4.8 电源日志。实现和实机验收范围见 [修复记录](battery-v0.4.15.md)；下文保留最初调查的证据和方案。

## 结论与用户确认的现象

用户最初描述为“70% 突然变成 0”，后续明确：设备屏幕还有 60%–70% 多，约十分钟后完全无法开机；电源键无反应，必须接入 USB 才恢复，并看到充电和空电。没有证据表明屏幕实际在相邻两帧从 70% 跳到 0%。

**已确认软件问题：百分比是未经本机容量标定的电压估计，且显示算法会长时间保留偏高数字，在低电时突然追赶。它不能可靠表示还剩六七成可用容量。**

**对这次无法开机的判断：真实欠压/供电不足应优先调查。** 电池容量不足、内阻偏大、充电未真正完成或异常负载均未被现场数据证实。当前证据不足以认定电芯损坏，也不足以把问题完全归于显示。M5PM1 官方低压保护行为与“电源键无法恢复、接外部电源后能启动”相容；是否实际触发仍需断电前 VBAT 和保护配置。[M5PM1 手册，低压保护](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1207/M5PM1_Datasheet_CN.pdf#page=28)

项目确有十分钟电池供电空闲关机，但用户确认普通电源键不能恢复，因此这项策略不能单独解释此次现象。后续测量需要标注该策略造成的关机，避免把它当成容量测试终点。

## 1. 已确认的显示问题

### 百分比并非容量测量

[battery_gauge.h](../firmware/src/battery_gauge.h) 第 12–13 行使用：

```cpp
percent = clamp((millivolts - 3300) / 8, 0, 100);
```

因此 3860mV 就被换算成 70%，4100mV 被换算成 100%。函数只接收时间和电压，不接收充电状态、供电来源、电流或电池实际容量。充电、拔线后的电压恢复、负载变化和容量衰减都没有进入容量模型。此前记录也明确完整放电和容量标定尚未完成，见 [implementation-status.md](implementation-status.md) 的 v0.3.12 记录。

M5PM1 提供电压读数，当前项目没有库仑计数据；沿用 SDK 的公式不等于完成 StickS3 电芯标定。电压估算受负载、温度、老化和恢复过程影响，需要针对电芯与使用工况测量，而不能任意套用另一种锂电池的表格。[TI 电压法 SOC 估算说明](https://www.ti.com/lit/an/sluaaa1/sluaaa1.pdf)

### 平滑叠加造成明显滞后

同一文件第 26–43 行依次做 7 点中值、1/8 EMA、2 个百分点迟滞，最后再限制为每五秒最多改变一个百分点。最后一层没有约束显示值与估计值的最大差距。

直接编译当前 `BatteryGauge` 的回放：稳定在 4100mV/100% 后，输入持续 3600mV（原模型约 37%）。约 148 秒后屏幕仍为 70%；约 308 秒才降到 38%，因迟滞最终停在比目标高一个百分点的位置。这是算法结果，不是此次真实电池的电压记录。

### 低电分支允许大幅跳变

第 35–36 行明确绕过普通限速：

```cpp
if (target <= 10 && shown_ > 10) {
    shown_ = target;
    stepAt_ = now;
    return;
}
```

由此产生“前面缓慢下降，后面突然变低”的不一致体验。以下均从稳定 3860mV/70% 开始，以每秒一次输入回放：

| 模拟输入 | 实际算法输出 | 解释 |
| --- | --- | --- |
| 持续 3200mV | 第 3 秒 69%，第 8 秒 68%，第 12 秒直接 9%；第 57 秒 0% | 已复现高百分比突然进入低电的路径 |
| 持续 2500mV | 第 3 秒 69%，第 6 秒直接 0% | 2500mV 是当前接受的最低有效值；仅为边界回放，不代表实机读数 |
| 连续无效 6 秒后恢复 3250mV | 70% → 未知 → 0% | 数据过期后的重新预热可以重新初始化为低电 |
| 连续无效 6 秒后恢复 3860mV | 70% → 未知 → 70% | 无效读取本身不直接制造 0% |

这种显示问题不会凭空消耗电池，但会让用户直到接近耗尽都缺少可信的低电提示。即使修好显示，也不能因此宣称真实续航变长。

## 2. 排除和仍待确认的路径

| 路径 | 本次发现 | 判断 |
| --- | --- | --- |
| Mac 错把设备电量解码为零 | `DeviceStatus` 没有电池字段；`device.cpp` 中 `level` 是 `audioLevel()`；屏幕直接读取 `powerBatteryLevel()` | 此次设备屏幕问题应修固件电量链路 |
| 普通 I2C 失败变成 0% | `power_status.cpp:30` 使用带 bool 成功状态的电压接口；失败送 -1；UI 显示 `--%` | 当前代码已区分未知与空电，不能套用便利接口失败返回零的解释 |
| M5PM1 空闲休眠首笔失败 | 固定驱动初始化会关闭该功能；可读回 0x09 检查实际配置 | 是诊断项，未证实发生 |
| 十分钟自动关机 | `idle_power.h:7` 的 600000ms 与 `ui.cpp:669` 的物理关机路径存在；与电池百分比无关 | 不能独立解释用户所述电源键无效；仍需在实验中区分关机原因 |
| 低电压保护/电池供电异常 | 用户现象与欠压后外部电源恢复相容 | 优先采集电压与保护配置，尚未定位到电芯、负载或供电路径 |
| 电池容量衰减、内阻增大或充电异常 | 没有电池侧电流、完整充放电记录或独立电压测量 | 未证实；不能直接建议更换电池作为确定修复 |

驱动 pin、寄存器、官方资料和版本差异的核查见 [一手资料笔记](battery-primary-sources-2026-10-13.md)。未找到可直接证明“升级 M5Unified 就能修复本次问题”的依据。

## 3. 本轮实测与证据边界

- 核对历史 42 份日志、1798 行 `[power]`。有效 VBAT 最低 3810mV，没有 `shown_pct=0`；所有有效 VBUS 样本均不低于 4000mV。这些日志不覆盖纯电池耗尽，不能用来否定用户现象。
- USB 基线确认真机 `v0.4.14`、运行 app1。启动后 5–30 秒记录的 VBAT 为 3928–3938mV，预热后显示 79%；VBUS 为 4942–4958mV，正在充电，`auto_off=0`。这只说明当前采样和显示能运行，不能证明当时真实 SOC 为 79% 或电池健康。
- 启动日志明确打印 `sleep 300s off 600s battery-only`。约 31 秒进入视觉睡眠并完成音频电路关闭，未在这段观察中出现异常重启。
- 初次打开原生 USB 串口时出现 `USB_UART_CHIP_RESET` / 下载等待。通过 watchdog reset 恢复应用，随后成功采集上述正常日志；没有写入或擦除 Flash。此调试副作用与用户在纯电池下的无法开机分开记录。
- 当前电量测试 9 组、闲置电源测试 9 组均通过。旧测试验证滤波和低电追赶，但没有验证“持续电压变化后显示与目标的最大偏差”，也没有验证真实容量。

## 4. 建议实施方案

### 第一阶段：同时修正显示滞后和补齐纯电池诊断

1. **取消无限滞后的固定步进追赶。** 保留抗孤立毛刺能力，对持续有效变化使用自适应跟踪。以“持续稳定输入后 30 秒内，显示距估计不超过 5 个百分点”作为第一版待实测调优的验收目标；该目标约束软件跟踪，不代表真实 SOC 精度达到 ±5%。小幅噪声维持迟滞。
2. **将低压告警与百分比动画分开。** 持续有效的低压需及时告警，不能等慢速百分比降下来；也不能只删除低电快速通道、让已耗尽电池继续显示高电量。可信低压应明确提示充电，无法确认的异常/过期读数显示未知。正常硬件保护保持不变。
3. **区分充电、外部供电和电池放电。** `BatteryGauge` 增加有效供电状态输入；供电切换时重新评估置信度，放电估计不直接继承充电时被抬高的显示。检测拔线使用已有供电来源/VBUS，不能用 CHG_STAT 下降等价代替。尚未标定前把百分比标为估计，充电时优先清晰展示充电状态。
4. **增加独立电池诊断快照。** 每秒记录单调时间、采样成功/新鲜度、VBAT、median/filtered/target/shown、VIN/PWR_SRC、充电态、亮度、传音/音效/无线方式；启动读回 PM1 版本、BATT_LVP(0x08)、I2C_CFG(0x09)，并记录可获取的复位/唤醒信息。记录不能假定芯片存在“上次低压关机原因”寄存器。
5. **通过已认证的 BLE/Wi-Fi 通道把诊断样本保存到 Mac。** 当前协议没有这些电池字段，需要增加低频诊断消息。避免依赖拔掉就中断、重新插上会改变电池电压且可能重启的 USB；RAM 环形缓存可辅助，但不能保证物理断电后保存。避免每秒写入 NVS。诊断采集本身不刷新活动计时，且需检查通信开销。

推荐先做这一阶段的小范围固件变更，验证后再做曲线标定。若配套修改并重新构建 Mac，按仓库要求运行 `scripts/build-macos.sh`，安装和联调固定使用 `/Applications/ThinCube.app`。

### 第二阶段：测清真实续航，再校准电量

- 从确认完成充电的状态开始，不以当前显示 100% 作为唯一充满判据。按现有充电芯片行为和有效充电状态确认，记录拔线时间。
- 先测试标准亮度、固定无线方式、无持续扬声器的轻负载，再比较传音/音效负载。将自动空闲关机明确记录为策略事件；用于容量测量的专用诊断运行可临时屏蔽空闲关机，但必须标记其与日常使用负载的区别，且不改变欠压保护。
- 记录断电前几分钟的 VBAT 和显示值。必要时由具备条件的人员在可访问测点交叉测量电池端电压、电流；USB 输入功率混有供电和充电，不能直接当作电池容量。
- 若 VBAT 已持续下降而显示仍高，确认估计/跟踪问题；若只有重负载时电压骤降，检查电芯内阻和瞬时负载；若轻负载下实际可用电量也明显不足，检查电池容量、充电路径及硬件。只有这些证据支持时，才进入电池检修或更换。
- 以本机电芯和代表性工况的测量建立分段电压曲线；电流积分可用于标定实际容量。需要稳定的高精度剩余容量时，再评估专用电量计；单靠平滑无法提供容量测量。

### 验收要求

新增回归场景应覆盖：充电后拔线、100%→低目标的持续输入、低压尾段、孤立毛刺、持续极低但合法读数、采样失效与恢复、负载后电压恢复，以及时钟回绕。保持 OTA 使用独立保守门限。

实机至少获得一次完整、可区分空闲关机和欠压断电的纯电池记录，并重复验证典型工况。验收应报告“关机前显示多少、是否有低电提示、真实续航多久、能否脱离 USB 重启”，不能只报告 USB 下百分比稳定。完成这一步之前，不声称已查明电池硬件根因或已修复真实续航。
