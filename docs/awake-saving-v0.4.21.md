# 按需开麦、静置渐暗与睡眠画面缓存 v0.4.21

实施日期：2026-10-14。用户授权实现三项续航优化，并通过 USB 烧录验证，保留语音、游戏与唤醒体验。本次沿用工作区已有的 v0.4.20 配对页修改，没有重建 Mac 上位机。

## 行为

- 关闭“声音互动”时，清醒待命不再因连接 Mac 或允许语音就持续采集。新倒立姿态形成时提前准备麦克风；手动开始和本次待完成的语音请求也会保持采集需求，等麦克风与 BLE 快速连接就绪才开始传音。停止、静音、失联与保持倒立时重新连接不会重放旧动作。开启“声音互动”仍保留原来的声音响应与采集行为。
- 按需停采后关闭闲置 ES8311；麦克风实际是否就绪与是否存在采集需求分开报告。原 Mac 客户端继续使用“倒立开始”/“重新翻转”待命提示，LCD 不会把主动停采画成麦克风故障；真正准备采集失败仍显示准备状态。
- 只有新鲜供电读数确认电池供电、IMU 正常且没有受保护任务时，静置 10 秒后用 1.5 秒将亮度降至保存亮度的约 35%，最低目标 12，且不提高原本较低的亮度。拿起、按键、配置操作立即恢复；用户保存的亮度不变。
- 语音及待完成的语音准备、游戏、旋转、配网、配对、OTA、模式切换、诊断、小剧场、电池校准和无效 IMU 输入不渐暗。USB/外部供电与未知供电维持原亮度；保护结束后给予新的渐暗窗口。
- 竖屏睡眠动画完成 1.5 秒后，仅在电量、充电/低压状态、连接或语音状态、显示方向变化时重新绘制及推屏。清醒、入睡/唤醒动画、横屏背景、游戏、小剧场和操作页面保持原绘制节奏。息屏后仍沿用停止绘制的既有路径。
- 原 30 秒视觉休息、朝下息屏、5/10 分钟待机/关机、深睡开关及控制心跳保持原协议；真实配置指令计为活动，控制心跳不延长空闲时间。没有调整音频采样率。

## 软件与构建验证

25 个 C++ 测试程序、5 个 Python 测试、78 项 Swift 测试通过；镜像身份测试使用最终产物单独通过。新增场景覆盖关闭/保留声音互动、新姿态预热、Mic/BLE 准备延迟、手动开始期限、按键边沿、游戏与手动会议、启动/重连/停止后的重新触发要求、故障提示、渐暗曲线、供电/任务保护、低亮度与时钟回绕、可见状态改变和睡眠缓存失效。新策略同时通过 C++11 编译，匹配固定 Arduino 工具链。

构建期间发现工作区的采集策略被另一个工作流程恢复为旧代码，因此停止该产物的使用，补回本次修改后从独立源码快照构建。最终构建前后已核对工作区与快照哈希，二者一致。

正式镜像 1719120 字节，SHA-256：`23904a5de33a0941ee817cfc9379c60104a441f7476ccd300bf02d3cf5ec6872`。静态 RAM 105600 字节，Flash 1718689 字节，未超过 2 MiB 应用槽。

## USB 安装与实机验证

读取实际分区表与 OTA 记录，确认活动槽为 `app1 @ 0x210000`；已备份原 v0.4.19 活动槽，仅向 app1 写入新应用，烧录数据哈希校验通过。未重写 NVS、bootloader、分区表、otadata 或 app0。现有 `/Applications/ThinCube.app` 0.4.11 自动恢复 BLE 连接。

临时关闭“声音互动”后，清醒状态读回 `mic_demand=0`、`audio ready=0`、`codec_off=1`，采集帧数连续保持 1849；USB 下保存亮度 134 未渐暗。手动开始语音后已确认进入传音。

- 停止首轮语音后，重新读回 `mic_demand=0`、`audio ready=0`、`codec_off=1`，采集帧数保持 14317，原 Mac 界面正常显示倒立开始的待命提示。
- 稳定竖屏睡眠时，多组 5 秒窗口记录为 `frames 0 / skipped 25`；电量改变的窗口为 `frames 1 / skipped 24`，证明可见状态改变仍会推屏。在线休息读回 CPU 160 MHz、BLE 间隔 90 ms。
- 从上述在线休息状态再次手动开始语音，成功恢复 240 MHz、BLE 快速间隔、保存亮度与采集。上位机累计接收计数从 30470 增至 32476，音频桥样本从 14524085 增至 15481220，补零计数维持 20，本次观察窗口新增补零 0 帧；累计等待从 2453 增至 2549 ms，这一统计不是端到端时延。
- 首轮较长语音会话中，设备采集队列丢帧为 0，BLE 发送队列累计丢弃 16 帧；没有把该轮报告成全程无线零丢帧。后续短轮用于复核休息唤醒与按需采集恢复。

- 用户拔下 USB 进行电池验证，并确认静置渐暗、拿起/按 A 恢复、倒立传音与翻回、两个横屏方向的游戏均正常。Mac 本地遥测记录 65 个电池供电样本，其中 20 个清醒渐暗样本读回亮度 103（过渡中）或 46（目标），保存亮度始终为 134；活动及电池语音期间恢复到 134。
- 用户插回 USB 后，BLE 连接保持正常。原“声音互动”设置为开启，验证结束已恢复开启；上位机确认开关开启且麦克风电平恢复。日常关闭此选项即可使用按需开麦，开启时仍保留原声音响应。

上述验收没有覆盖 Wi-Fi 音频、端到端首音时延或每个配网/OTA 故障路径；这些保护条件由回归测试和既有控制流程覆盖。所有镜像、备份、源码快照、编译/测试/烧录及实机记录位于本地 `artifacts/awake-saving-v0.4.21/`。本次没有测量电池侧电流或续航增幅。
