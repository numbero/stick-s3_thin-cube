# 倒立开机与唤醒进入对讲：v0.4.62

2026-10-22。固件修改、完整本地回归、正式构建、USB 安装及倒立重启/重连/朝下息屏拿起的实机检查通过；用户确认拿起后自动进入对讲。本次不修改或重建 Mac 应用。

## 问题与修复方案

旧实现只把“其他姿态变为倒立”当作一次启动手势。首次开机识别倒立时，`PoseVoiceController` 直接记录初始姿态并返回；随后 `VoiceState::setPose` 遇到相同姿态也直接返回。如果倒立发生在 Mac 音频连接、唤醒或其他临时条件恢复之前，这次手势同样会被消耗，之后保持倒立也无法进入对讲。纯电池下的 PM1 深睡唤醒会重建主控状态，因此可以再次遇到开机路径的问题。

v0.4.62 将已确认倒立作为持续的姿态请求，每轮按当前条件重新核对。将暂时暂停与明确中止分开：

| 场景 | 新行为 |
| --- | --- |
| A 键在上的倒立姿态开机、PM1 深睡后重启 | 正常确认倒立，等待连接和采集条件就绪后自动进入对讲 |
| 屏幕朝下在线休息后直接拿成倒立，唤醒比姿态确认晚 | 唤醒后根据仍有效的倒立姿态进入对讲 |
| Mac 音频连接尚未就绪、断连或心跳超时 | 立即清理旧会话和快捷键；条件恢复且当前姿态仍确认倒立时建立新会话 |
| 临时忙碌、麦克风或无线速度恢复延迟 | 保留姿态请求，条件满足后启动 |
| 用户停止、静音、禁用语音、校准或游戏隔离 | 保留中止语义，本次运行内保持倒立不自动重开；离开倒立后重新进入，或 Mac 手动开始 |
| 手动持续会话 | 不被自动姿态请求替换；正常竖持时失联的手动会话不自动重开 |

配对重置、诊断等原本显式中止会话的入口继续沿用中止路径。中止标志不写入 NVS；重新开机按新的开机姿态规则处理。语音禁用、静音、休眠、受保护任务或音频对端未就绪时仍不传音。

## 实现

- `VoiceState` 增加 `poseRearmRequired`，`pause()` 释放音频和快捷键但保留姿态资格，`stop()` 锁住当前姿态请求。相同倒立姿态也会检查能否启动，且不会覆盖等待中的手动开始。
- `PoseVoiceController` 首次观察到已确认倒立即走正常启动路径；开机和恢复也可预热采集。保留校准、游戏隔离及停止后的重新翻转行为。
- 正常倒立确认保持原 220 ms，角度、语音退出回差、朝下休息和 5/10/20 分钟期限均不变。IMU 必须健康，候选与稳定姿态必须一致才可新启动；活动会话原来的倾斜容错继续保留。
- 深睡准备和连接方式切换使用暂时暂停；显式停止、静音等继续使用中止。
- 每次新音频会话递增内部代次。即使同一轮主循环内发生暂停与恢复，仍更新传音 nonce、清空旧边沿和手势，并重建 A/B 按键上下文。已经按住的按键不会跨会话重放，须松开后重按。
- `voiceBlock=rearm` 仅表示被中止的倒立请求，线协议和 Mac 兼容性不变。
