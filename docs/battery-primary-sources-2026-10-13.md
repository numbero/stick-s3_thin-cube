# StickS3 电量突降：一手资料核查

调研日期：2026-10-13。对象为 K150 StickS3 和当前项目固定的 M5Unified `8b63555e7bd9ac71978c55ad868fd1d1d3b2ef3e`（0.2.23）。本文补充硬件与驱动证据；没有用其他 Stick 型号的经验代替本机实测，也没有认定电池损坏。

**现象澄清**：用户后续描述是“屏幕显示六七成电量，约 10 分钟后完全没电”，并确认电源键无反应、必须接 USB 才恢复且显示空电；没有确认看到百分比直接变成 0。项目虽有电池供电下 600000ms 空闲自动关机策略（`idle_power.h` / `uiPowerTick()`），仅靠这项策略不能充分解释电源键无法恢复。应重点检查显示虚高和实际欠压，电池容量与硬件异常仍待实测；本文不把任何一项假设当作已经确认的完整根因。

## 已确定的事实

### 1. 百分比是电压估计，不是芯片给出的剩余容量

M5PM1 的 `VBAT_L/H`（0x22/0x23）提供毫伏读数。其公开寄存器表没有剩余容量、累计电荷或 SOC 寄存器。[M5PM1 手册 V1.9，第 17 页](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1207/M5PM1_Datasheet_CN.pdf#page=19)

当前固定版本的 `Power_Class::getBatteryLevel()` 对 PM1 使用线性换算 `(mv - 3300) * 100 / (4150 - 3350)`，因此截断后的端点实际是 3300mV/0% 和 4100mV/100%。项目 `BatteryGauge::voltageLevel()` 的 `(mv - 3300) / 8` 延续这个模型。70% 对应约 3860mV，只是该模型的结果。[固定版本 Power_Class 源码](https://github.com/m5stack/M5Unified/blob/8b63555e7bd9ac71978c55ad868fd1d1d3b2ef3e/src/utility/Power_Class.inl#L2418)

本次检查的官方产品页、手册、示例与驱动没有提供 K150 内置 250mAh 电芯的经标定放电曲线。因此，没有依据把网上任意锂电池曲线称为 StickS3 的准确 SOC 曲线。

### 2. 当前驱动已区分读取失败，且连续读取两个字节

本地依赖库 `git rev-parse HEAD` 与上述 pin 一致，`git status --short` 为空。其 `getBatteryVoltage(uint16_t*)` 从 0x22 一次连续读取两字节；读失败返回 `false`，成功按小端组合。无参便利接口失败时返回 0，但项目调用的是带成功状态的接口，并把失败作为 -1 送入电量计，不能将两种接口混为一谈。[固定版本 M5PM1_Class 源码](https://github.com/m5stack/M5Unified/blob/8b63555e7bd9ac71978c55ad868fd1d1d3b2ef3e/src/utility/power/M5PM1_Class.inl#L328)

公开手册未说明 VBAT 高低字节是否在读事务期间锁存；当前代码没有把两个字节拆成两笔读取。没有发现可证实本次异常由“16 位读撕裂”导致的官方勘误。若以后怀疑读取一致性，应记录原始两字节、事务结果和相邻样本，再复核；不能先断言库存在此缺陷。

### 3. 空闲休眠首次通信失败属已知机制，但当前配置主动关闭该功能

M5PM1 手册说明：`I2C_CFG[3:0]` 为 0 时关闭空闲休眠；启用并进入休眠后首笔 I2C 通信只用于唤醒，会失败，后续通信才正常；唤醒后 300ms 内还需收到完整地址。休眠流程包含 ADC 外设复位。[M5PM1 手册，第 14、26 页](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1207/M5PM1_Datasheet_CN.pdf#page=16)，[官方 StickS3 低功耗教程](https://docs.m5stack.com/en/arduino/m5sticks3/m5pm1)

但当前固定版本的 `M5PM1_Class::begin()` 会写 `I2C_CFG=0x00` 关闭空闲休眠。因此，休眠只能作为配置异常时的检查项，不能据此解释本次 70%→0。该初始化代码没有检查这笔写入的返回值；读取 0x09 可确认实机配置是否真的生效。[固定版本初始化代码](https://github.com/m5stack/M5Unified/blob/8b63555e7bd9ac71978c55ad868fd1d1d3b2ef3e/src/utility/power/M5PM1_Class.inl#L69)

### 4. 负载与充电状态确实会影响电压读数的含义

官方原理图总览标注充电 IC 为 LGS4056；电源页标注充电电流 190mA，并显示 `PYG0_CHG_STAT`、`CHG_EN`、`VBAT_ADC` 和 `VBAT_ADC_EN`。这支持“充电控制/状态和电压采样”的硬件模型，不能据此推出有库仑计。这里不援用未核实型号后缀的第三方 4056 手册，也不推断其具体充满/复充阈值。[StickS3 V0.6 原理图，第 1、2 页](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1207/K150_Stick_S3_PRJ_V0.6_20251111_2025_11_17_16_10_24.pdf)

官方规格给出 250mAh 电池，L3A 参考电流 36.69mA、满载参考电流 519.02mA（均为 4.2V 测试条件），并提示电池供电时扬声器音量低于 75%，以避免高功耗引发意外重启。这证明应检查负载关联性，不证明用户的设备已经出现相同问题。[StickS3 官方产品页](https://docs.m5stack.com/en/core/StickS3)

TI 的电量估算应用说明指出：端电压换算 SOC 受负载变化、温度、老化和电压恢复过程影响；标定曲线需要记录实际放电电压和电流，低电流、近似恒流和相同温度下更准确。该资料支持估算方法的限制，不是对 StickS3 具体电芯的标定。[TI SLUAAA1，第 2、4 页](https://www.ti.com/lit/an/sluaaa1/sluaaa1.pdf)

M5PM1 还会在无外部供电、VBAT 低于 `BATT_LVP`（0x08）时自动关机；重新开机可由电池电压超过阈值 100mV 或外部供电插入满足。该机制与“电源键无反应、接 USB 才恢复”相容，但没有当时 VBAT 和 0x08 读数，仍不能断言已触发。显示 0% 的 3300mV 阈值与硬件保护阈值是不同参数。[M5PM1 手册，第 14、26 页](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1207/M5PM1_Datasheet_CN.pdf#page=16)

### 5. 官方升级记录不能直接当成本次修复依据

查询时官方发布列表已列出 0.2.26。历史 0.2.20 的电池 ADC/`analogRead` 冲突修复指向 StickC Plus2 等直接 ADC 计量设备；StickS3 经 PM1/I2C 读电压，不应套用该结论。0.2.21 的 PM1 修复涉及电源来源位图、按键和唤醒 IRQ。已读取的发布说明未给出可直接对应“StickS3 电量 70%→0”的修复证据。[M5Unified Releases](https://github.com/m5stack/M5Unified/releases)

线上 `master` 的 PM1 读取函数仍表现为连续两字节读取、带失败返回。由于没有成功取得 0.2.26 对应文件的稳定快照，本次不声称已完成 pin 与最新版全量差异审计，也不建议把升级库作为已验证的解决方案。[线上 master 源码](https://raw.githubusercontent.com/m5stack/M5Unified/master/src/utility/power/M5PM1_Class.inl)

## 对本次排查的可执行建议

以下为结合项目代码的工程判断，待回放与实测验证：

1. 电量显示算法存在独立的滞后风险：7 点中值、EMA 之后，又以每 5 秒 1% 追赶，再在估值≤10%时绕过追赶直接跳低。它允许显示值长期高于电压估值，随后突然下跳。修复目标应同时约束跟踪偏差、响应时间、低电告警时限；仅增加平滑会掩盖真实低电。结合用户电源键无法恢复的描述，应同时排查欠压，不能只调整空闲关机时间。
2. 保留“读取失败/陈旧/未知”和“确认低电”的区分；不要将 -1、断连或恢复预热转换成 0%。对连续合法但极低的读数，需要单独记录并确认，不能和 I2C 失败共用策略。
3. 采集一次受控插拔 USB、亮屏/息屏、Wi-Fi 与音频负载切换日志，记录 `raw_mv/median_mv/filtered_mv/shown_pct/ota_pct`、I2C 成功状态、供电来源、充电状态、运行时间与重启原因。单次 USB 供电基线不能验证放电尾段。
4. 若实测出现低压，优先用外部电压测量交叉核对；真实端电压下降与 ADC/I2C 数值异常需要不同修复。正常保护仍开启。不要通过降低关机阈值来改善电量显示。
5. 再按实际设备负载建立放电曲线，区分充电、外部供电和放电阶段；曲线未标定前将百分比视为估计。若要求准确的剩余容量，需要电流积分/专用电量计等额外依据，软件滤波本身不能创造容量测量。

证据边界：目前官方资料能够解释测量链路和潜在影响因素，不能证明用户那次突降前电池电压、I2C 状态、供电切换或负载的真实情况；触发条件仍需现场日志确认。
