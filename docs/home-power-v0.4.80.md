# 清醒主页省电 v0.4.80

2026-10-26。首轮优化进入深睡前的清醒负载，已完成代码、回归、固件构建及 ThinCube-38DBE2 的 USB 安装与短时 BLE 实机验证。Mac 仍使用正式 /Applications/ThinCube.app 的 v0.4.39，没有重新构建。尚未实测电池侧电流或续航增幅。

## 行为

- 正常竖屏主页的 idle／charging 状态，在启动检查通过、IMU 健康且无受保护任务时，CPU 从 240MHz 降至 160MHz。
- 环境声纹保持连续采音；本地 RMS 不再每轮调用性能模式，避免与主页省电反复切换频率。
- 主页省电与在线待机分开。主页沿用约 30fps、原底层 IMU 频率和快速 BLE 连接；只有原有休息状态使用较慢输入／绘制／BLE 档位。
- 主页完整状态 JSON 的常态构建从每 40ms 改为每 200ms；实际命令、配置和脏快照仍可立即重建。200ms BLE 快速状态、控制租约及快捷键事件的时限沿用原值。
- 真正传音／预备传音、音效、游戏、旋转、配网、配对、OTA、诊断和特殊任务恢复性能档。小剧场和光点在电源策略之后获准启动时，也在第一帧前立即恢复满频。
- 电源遥测 onlineSaving 覆盖主页及在线待机；cpuMHz 继续报告实际 CPU 频率。USB 心跳补充实际采音率，便于验证。

本轮没有降低界面帧率或修改 5/10/20 分钟策略，没有更改 IMU／FIFO、广播间隔、协议、配对设置或校准。

## 采样率的实施选择

保留 BLE 16kHz 和 Wi-Fi 48kHz。固定 M5Unified 的 Mic.end 会停止任务并执行 codec 关闭；改变采样率也需要重建采音通路。Mic 的公开接口注明 ES8311 重新上电后可能经历约一秒的零样本预热。因此，首轮不把 Wi-Fi 本地采音改成 16kHz，避免在环境声纹接管为传音时新增一次热身。

后续只有在验证出不增加首帧延迟的切换方案后，再单独试验环境采音降采样。本轮收益来自 CPU 和重复状态构建的削减，不将采样率降低计入收益。

## USB 安装与实机结果

设备 MAC 7c:e8:b1:e2:db:38。先读取并校验完整 8MiB Flash 备份，再向备用 app0（0x10000）写入新版；镜像核对后只更新一份 OTA 选择扇区为 seq=17／NEW。原 app1／v0.4.79 及 seq=16／VALID 选择记录保留。启动前逐项核对 bootloader、分区、NVS、回退应用与回退选择记录未变。

首次重启 USB 重新枚举，因此没有反复打开串口打断试启动。等待超过 90 秒后只读检查，确认 app0／v0.4.80 的 seq=17 已变为 VALID，镜像摘要仍匹配、回退完整；功能测试前 NVS 也与备份逐字节相同。正式 Mac 应用自动重连，不需要重新配对，两项姿态校准仍有效。

随后在同一个正常启动会话中观察至运行 175 秒：

- 临时开启原本关闭的声音互动，连续真实环境采音时主页稳定为 160MHz，采样率 16kHz，绘制约 29fps。两段主页采音共取得 12 个五秒心跳检查点，帧计数持续增长，没有逐轮 160／240MHz 抖动。
- Mac 手动开始持续语音后立即进入 240MHz，持续传音取得 12 个五秒检查点，跨度超过 50 秒；停止后恢复 160MHz 和本地声纹。采音计数在接管前后连续，没有重启 codec 的日志。
- 全部已记录的设备采音 dropped=0、BLE 音频队列 drops=0、BLE notify failed=0、IMU errors=0、电源读取 failures=0，health=1，未发现崩溃标记。
- 主页省电时 BLE 遥测保持 15／30ms 的快速连接档。静置后原有约 30 秒视觉休息仍会停采、关闭 codec，并协商到 90ms；这与五分钟在线息屏、十分钟主控断电的阶段不同。
- 测试结束已停止传音，恢复声音互动关闭、扬声器静音开启；语音允许、麦克风非静音、增益 1、保存亮度 32、自动连接偏好和校准保持原值。USB 监视器已经结束并释放端口。

Mac 音频诊断界面当时显示接收 5,596 帧、写入音频桥 2,644,931 样本、补零 94 帧，累计等待 3,040ms。这些计数器不会在会话切换时清零，不能归因于本次固件改动，也不能把累计等待当作端到端延迟。因此本轮结论是设备侧采音与频率切换正常，不声称无线链路零损失或音质／延迟已完成对照验收。
