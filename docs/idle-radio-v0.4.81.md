# 双敲按需采样与离线广播省电 v0.4.81

2026-10-26。固件 v0.4.81，Mac v0.4.43（64），待发行清单 0.4.82，协议保持 v1。

## 双敲 FIFO 按需运行

普通主页、横屏和休息状态不再持续生成、读取、解析软件双敲 FIFO。已有的倒置传音上下文或显式手持实验模式准入后恢复，离开后暂停。加速度 200Hz、陀螺仪 100Hz、普通姿态读取间隔、识别参数、稳定等待与按键防护均保持原值。

每次重新独占采样都清空旧 FIFO、重置软件样本时钟和识别器，避免把上个场景的单次冲击带入新场景。配置保存仍验证 FIFO 的启动与恢复；事务失败会解除识别准入，不反复尝试或产生快捷键。

软件识别与 USB 显式波形记录共享 FIFO。退出传音不会中断仍在运行的诊断记录；结束记录也不会关闭仍需识别的 FIFO。附着到已有记录时，识别器跳过第一批可能早于上下文的样本，波形记录保持连续。最后一个使用方释放后，恢复原寄存器并清空缓存。

Mac 双敲设置页将健康、已验证且处于非识别场景的暂停显示为「双敲待命」；实际应运行却未运行时仍显示未就绪，异常仍按异常显示。

## 离线广播分档

- 开机或断连后先维持原 30–60ms 快速广播窗口。
- 连续 60 秒没有按键或有效拿起／运动，改为 500–1000ms 广播参数。
- 按键、实际运动会恢复快速广播；配对、连接设置及连接切换期间维持快速档，退出后重新计算 60 秒窗口。
- 已连接时仍使用原来的连接间隔及语音恢复策略。广播分档只作用于未连接状态。

广播启停由主循环统一执行，等待 GAP 完成回调后才进行下一步；活动发生在慢档切换途中时，重启时重新选择最新档位。连接会使旧广播请求失效；即时 API 拒绝和异步失败均退避一秒再尝试。心跳、角色动画及后台状态刷新不延长快速广播窗口。

同一个正常运行会话观察约十分钟：

- 普通主页及休息阶段，两次快照相隔 118,092ms，软件双敲样本数均为 0；姿态输入持续健康，无 IMU 错误。
- 显式 USB 波形记录取得 653 个 200Hz 样本，结束后恢复成功；未改变双敲参数、保存状态或配置记录。
- 用户完成两组「平放→倒立→双敲→平放」操作。每次倒置传音均开启软件 FIFO，两次实际双敲均 accepted，blocked=0；回到平放均停止传音并恢复 FIFO 寄存器。最终 softwareSamples=3899，之后约 178 秒仍为 3899。
- 退出 Mac 应用并保持设备静置，日志确认从快速档切到 500–1000ms 慢广播。随后从系统应用目录重新启动 Mac，自动发现、加密并连接原设备。首次离线观察受到拿起动作影响，快速窗口按预期重置；最终静置观察单独完成。
- 记录期间设备采音 dropped=0、BLE 音频队列 drops=0、notify failed=0、IMU errors=0、电源读取 failures=0。这里是设备计数器观察，未作为端到端音质或时延对照结论。
