# 连续健康自检与完成页自动返回 v0.4.75

2026-10-24。完成页改为 5 秒倒计时自动回日常界面，保留新的 A/B 短按提前继续；A 方案徽章和主要布局不变。

## 自检依据与实现

原有 60 秒是项目自己的等待门槛，不是 SDK 的固定时长要求。与当前框架对应的 [ESP-IDF v4.4.7 OTA 文档](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32s3/api-reference/system/ota.html#unexpected-reset)要求新版启动后做自检、通过后由应用确认，并建议尽快完成自检以缩短首次启动掉电导致回滚的窗口。

新版使用实际持续观察的 15 秒健康窗口，正常预期约 15–20 秒完成：

- 屏幕缓冲、屏幕尺寸及首次画面真实推送就绪；
- IMU 的加速度与陀螺仪采样有效且新鲜；
- 本地运行资源与所选无线服务就绪，不要求联网、配对或 Mac 连接；
- 需要本地采集时麦克风已就绪且已交付帧，静音/关闭采集时不额外强制采集。

任何条件失败、元数据读取失败或主循环两次健康观察相隔超过 250 ms，连续窗口都重置。确认写入失败时继续显示自检并重新观察，不提前显示完成。启动 90 秒仍 pending 则请求回滚；超过该截止时间不再允许确认。未确认期间的意外重启仍由 bootloader 回滚。

只有 IDF 实际确认成功才开始完成页的 5 秒计时；显示 `CONTINUE IN 5 s` 到 `1 s`，结束后回到正常 UI。这个时钟独立于 HTTP OTA 服务，在未联网或连接设置过程中也运行。普通 VALID 开机不经过完成页。手机只报告写入待确认，同步调整为通常 15–20 秒的等待说明，并提示完成页会自动退出。
