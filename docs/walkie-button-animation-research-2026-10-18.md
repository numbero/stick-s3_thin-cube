# 对讲机 A / B 独立 Clawd 动画调研

日期：2026-10-18。基于当前工作区 v0.4.41 双键实现、已锁定 Clawd 角色规范及一手交互设计资料。本文为方案调研；本轮没有修改产品代码、构建应用或烧录设备。

**最终决定（2026-10-18）：用户选择保留当前 A/B 统一动作，以下差异化方案暂不采用。** 任一按键保持时共用抬机、绿灯反馈，两枚都松开后回待命；本次提交不修改 `pet.cpp`。下文保留为调研记录，关于 A/B 分离和 A 专属灯色的建议不作为本次实施要求。

## 结论

可以实现，第一版适合做成**按键身份对应固定动作**：A 保留念力抬机，B 增加凝神点头与方块念力脉冲，A+B 可以组合。快捷键的实际内容继续由 Mac 自定义；动作不绑定“发送”“取消”“转写完成”等业务含义。

当前固件已区分 A/B 的本地保持状态，只是在交给角色绘制时合并成 `deviceHeld()`。因此两枚键现在都会抬起同一台对讲机并变绿。将动画输入分开即可，无需重新设计快捷键协议、Mac 注入逻辑或角色图片资源。精确源码依据见[独立代码核对笔记](walkie-button-animation-code-evidence-2026-10-18.md)。

本方案的动画表示“设备在对讲机上下文中接受了这枚按键”。固件不知道 B 是否绑定，也不知道 Mac 或目标应用是否实际执行；现有 ack 确认边沿处理，不能作为执行成功回执。

## 推荐动作：同一角色、同一道具、两种反馈

| 状态 | Clawd 与道具 | 灯色与提示 | 松开时 |
| --- | --- | --- | --- |
| 无键 | 对讲机在身侧悬浮，保持当前待命造型 | 对讲机红灯；LIVE、音量条继续反映传音 | 保持待命 |
| 仅 A | 保留现有动作：对讲机浮到脸侧，视线追随，触角微竖，身体轻微回应音量 | 对讲机绿灯；A 保持标记 | 立即释放快捷键，对讲机缓降回身侧，灯恢复红色 |
| 仅 B | 短暂凝神、身体轻点头约 1–2 屏幕像素，一侧触角抬起；两枚琥珀方块在角色右上方作短距离念力脉冲；对讲机仍在身侧 | 对讲机保留红灯；B 保持标记与方块形状共同区分 | 立即释放快捷键，B 表情与方块自然收回 |
| A+B | A 的抬机位置和绿灯保留；叠加 B 的凝神、触角和方块 | 同时显示 A、B 保持标记 | 分别撤掉对应动作；另一枚键继续保持，不整体回待命 |

这里的红灯仍沿用原角色定义，表示 A 未保持，不能用来判断麦克风是否静音。实际采集和传音继续看 LIVE 与音量条。当前 B 也变绿是合并输入造成的结果；拆开后应回到已锁定的 A 灯色语义。[角色规范：语音与念力对讲机](clawd-character-v2.md#L18)

动作不依赖颜色才能识别：A 的主要区别是道具位置，B 的主要区别是表情与离散方块，并配 A/B 字样。这借鉴了 W3C 建议以形状或文字补充颜色的原则；此处是硬件反馈设计参考，不是对设备做 WCAG 合规声明。[W3C：Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

本轮附可切换 A、B 和双键状态的交互概念预览。预览复用当前 66×52 角色几何和 135×240 屏幕比例，新增动作是设计草案；声音电平为示意数据，没有连接设备或注入键盘事件。最终像素幅度和缓动以真机观感为准。

## 其他可选方向

| 方向 | 优点 | 代价与判断 |
| --- | --- | --- |
| **同一对讲机，B 叠加专注动作（推荐）** | 延续已确认角色，动作可组合，低资源开销，适配任意 B 快捷键 | 首次需要用 A/B 标记帮助建立对应关系 |
| A 用对讲机，B 唤出悬浮键帽 | 区分更强，键帽也能表达通用快捷键 | 135px 宽度中双道具拥挤；A+B 的布局和遮挡成本明显增加，适合后续完整场景迭代 |
| 在 Mac 为每枚键选择动作 | 用户能按自己的快捷键用途挑反馈 | 需要动画目录、设置存储、设备同步及兼容逻辑；适合作为第二阶段能力 |

不建议直接把 B 映射到现有 `PET_EXCITED`、`PET_UPSET` 或 `PET_DIZZY`。它们有完整情绪时长和身体动作，部分会被语音分支覆盖，部分粒子仍可能混入；重复按键还可能重置全局情绪时间。给 B 增加对讲机专用叠加层，效果和边界更清楚。[pet.cpp](../firmware/src/pet.cpp#L44)

## 动作时序与打断

以下是待真机调校的起始参数，不是已测量结果：

- 按下后的首个可绘制帧立即响应；B 的凝神进入约 100–160ms，保持时用约 0.9–1.4s 的轻量周期，松开约 120–180ms 收尾。
- A 沿用原缓动观感。源码的 85ms、130ms 是渐近追随的时间尺度，不能理解为整个动画的固定完成时长。
- 很短的点击可保留约 120ms 的小方块尾迹，使操作可见；A/B 保持字样、灯色和真实 key-up 仍按逻辑状态立即更新。尾迹不延长快捷键，不排队积压多次点击。
- A+B 不做“最后按下覆盖全部”。A 控制对讲机抬升和灯色，B 控制专注表情和额外方块；两者的身体位移相加后限幅。
- 退出、静音、进入系统操作页、快捷键上下文失效时取消按键动作；不在重连或重新进入模式后补播旧动作。道具是否收回仍取决于真实传音状态。
- 对讲机动画保持无声，避免为按键音切换正在使用的音频通路。

预览遵循系统“减少动态效果”偏好，用静态姿态和 A/B 标记保留区分。若以后给设备增加动态效果设置，可采用相同降级方式；首版不必为此扩展 Mac 设置页。W3C 对交互动画的资料建议减少不必要的动态效果，并支持用户的运动偏好。[W3C：Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

## 最小实施路径

1. **提供动画专用只读输入。** 在 `device` 内返回 `live / heldA / heldB`。A 取最终 `voice.held`，兼容旧 Mac；B 取已通过双键上下文与武装门槛的 `walkieKeys.heldB`。保留现有合并的 `deviceHeld()` 给原状态文案、故事和文字门控，不能直接改成只返回 A。
2. **增加独立动作策略。** 在 `deviceTick()` 之后统一更新一次 A/B 姿态、边沿和收尾，`petDraw()` 消费结果。处理场景取消和短按；避免把按下检测分散到不同绘制入口，或依赖“某帧刚好绘制了”才记录事件。
3. **修改局部程序化绘制。** 原 `visible` 继续跟随传音；将原 `lift`、灯色和抬机屏幕刻度交给 A；新增 B 的小幅表情、触角和两枚方块。保持无嘴、无手臂、无腮红、悬浮物与身体留间隙等角色约束。
4. **对齐已有按键提示。** 竖屏页脚目前仍固定写 `B:MUTE`；双键对讲机上下文显示 `B:KEY`，其他模式和未协商双键时保留静音提示。保持当前模式边界，不扩展 B 在其他模式的功能。
5. **针对性验证后再上真机。** 动作策略验证状态组合、短按、取消和快速切换；视觉确认小屏可辨识、无裁剪、无大幅跳动，且没有拖慢持续音频与 UI。

第一版涉及 `device` 只读接口、一个轻量动作策略、`pet` 绘制、主循环更新点和页脚提示。无需新素材播放器、图片下载、动画帧大数组、Mac 键位编辑器或通信字段。工作量主要在动作调校与边界验证，当前未对新增动作做固件性能实测。[渲染与调用链证据](walkie-button-animation-code-evidence-2026-10-18.md#渲染链与坐标证据)

当前常规绘制间隔为 33ms，约 30fps；操作或低功耗状态会使用其他节奏。动作采用毫秒时间推进，不按帧数累计，也不用阻塞等待。对讲机道具延伸到身体原 66 单位边界之外：竖屏最右约 129px，而横屏接星还有 73×63 裁剪区域，新增方块必须连同道具检查边界。[main.cpp](../firmware/src/main.cpp#L186)、[ui.cpp](../firmware/src/ui.cpp#L1179)

## 必须覆盖的语义边界

| 场景 | 方案要求 |
| --- | --- |
| B 未设置快捷键 | 新 Mac 仍可协商双键，设备仍能接受 B，播放中性的 B 动作；不能提示“已执行”。如果要求未绑定时完全无动画，需要额外同步绑定状态，应另立需求 |
| 旧 Mac / 尚未协商双键 | 保留 A 原动画；B 仍按原静音/系统功能处理，不播放对讲机 B 动作 |
| 进入模式时已按着 A 或 B | 遵守既有防预按规则，先松开再按才响应；不能读取 raw 按键绕过策略 |
| A+B 分别松开 | `AB→A` 保留抬机与绿灯；`AB→B` 放下对讲机、恢复红灯、B 动作继续；`A/B→无键` 保持传音待命 |
| 按住退出、断线、静音、休眠、系统页接管 | 清除对应动作，不延迟松键，不把退出后的松手再解释成其他按键事件 |
| Mac 先触发 400ms 状态超时保护 | Mac 可能先清键，而设备短时间仍显示本地保持姿态；动作不能宣称精确镜像 Mac 按键状态。现有边沿 ack 无法消除这个语义差异 |
| 横屏游戏 / Mac 手动音频会话 | 传音道具沿用既有规则；只有符合快捷键上下文的本地 A/B 才触发相应反馈，不能把游戏 A 或普通 B 静音误画成快捷键 |
| 隐藏页面后返回、低帧率、快速连按 | 没有旧动作补播、残留保持、重复进入动作、方块越界或动作队列积压 |

这些边界直接继承当前本地按键、Mac 注入和断连策略，完整源码引用与接口草案见[证据笔记](walkie-button-animation-code-evidence-2026-10-18.md#必须保留的边界行为)。此前 B 快捷键的实体验收验证了按键行为，本轮的动作预览尚不等于新增动画的实体验收。
