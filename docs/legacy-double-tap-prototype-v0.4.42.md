# Legacy 双敲诊断原型 v0.4.42

日期：2026-10-18。用户确认采用手持机身双敲路线。本原型单独构建为 `v0.4.42-legacy-diag`，保留默认 Base 构建。**没有新增上位机快捷键、协议事件或自动发键。** 原有 A/B 行为沿用当前工作区实现。

目标交互已由用户明确为：**正常对讲握姿，敲击设备正面 A 按键上方**。此前按背面安排的实验仅保留为探索数据，不能代替目标位置的验收。

## 实现

- [ImuService](../firmware/src/imu_service.cpp) 在 Legacy 构建中独占初始化、六轴采样和状态消费；关闭 M5Unified 自动 IMU 初始化，继续使用其 I²C、屏幕、音频和电源。
- 固定 [Bosch SDK](../firmware/lib/BoschBMI270/UPSTREAM.md) 提交 `41129fc…`，保留许可证，修复此前复现的 tap 页复制越界，并用实际 SDK 源码执行 ASan/UBSan 回归。
- 加速度 200 Hz / ±8g，陀螺仪 100 Hz / ±2000°/s。原始数据按 M5 的 g、°/s、传感器坐标 raw16.16 偏置和 `X=+Y/Y=-X/Z=+Z` 输出；读取旧偏置，不修改 NVS。没有旧 M5 偏置时明确使用零偏置，不新增静置校准。本机日志为 `offsets=zero`；静态加速度与升级前接近，完整六面及转轴仍待人工验证。
- 只启用 double tap；Z 轴、灵敏度系数 9、400 ms 手势窗口、400 ms 安静期、等待窗口结束分类。参数显式写入并读回，可通过 USB 切 X/Y/Z；这些是实验起点。
- 片上状态和六轴 data-ready 由同一轮询消费，以新状态触发计数，不靠输出值变化判断事件。主循环目标至少间隔 10 ms，实际受绘图/控制任务影响，记录最大间隔；状态位不能充当无损队列。
- `raw` 是芯片报告的双敲数，`accepted` 是经过场景/按键/进入稳定期/冷却过滤的诊断数，`blocked` 是拦截数，`unknown` 是不符合仅双敲预期的事件。每次报告记录时刻、模式、姿态及按键。计数不代表已知真实动作的识别率。
- 默认只在倒置传音中接受事件；`tap on` 临时开启手持实验模式，放宽语音条件，仍拦截 OTA、配网、配对、游戏、休息及休眠准备。A/B 按下及其后约 500 ms 拦截，进入场景后等待 500 ms，接受事件后冷却 600 ms。启动、重新配置和休眠恢复清状态并重新武装。
- 现有姿态、显示旋转、摇晃动画和游戏继续读取兼容的六轴快照；校准及 OTA 健康检查要求新鲜数据。休眠按 Legacy ANY_MOTION 的 page 1 / `0x36` 配置，保留邻接字段和 PM1 事务；睡前关闭 tap，取消后恢复，失败重新初始化仍使用 Legacy。

## 构建与诊断

```sh
cd firmware
pio run -e m5stack-sticks3-legacy-diag
# 保留的 Base 回退构建：
pio run -e m5stack-sticks3
```

不要直接以普通 `pio upload` 覆盖已使用设备的整套启动分区。此次安装先完整备份，再只更新确认的活动应用槽；原配对、设置、校准、OTA 数据和备用槽校验保持一致。

USB 命令通过已有调试入口处理。打开串口可能复位设备，尽量保持单一连接：

| 命令 | 用途 |
| --- | --- |
| `tap status` | 配置、健康、错误、轮询最大间隔和计数 |
| `tap on` | 手持实验模式，不要求与 Mac 建立语音会话 |
| `tap auto` | 回到默认对讲机语音场景 |
| `tap off` | 停用片上敲击，六轴继续采样 |
| `tap reset` | 清诊断计数和最大间隔 |
| `tap axis x` / `y` / `z` | 切检测轴并重新配置、清状态 |
| `tap sleepcheck` | 空闲时执行真实睡前寄存器配置及撤销，不发关机命令 |

既有屏上诊断页新增 raw / accepted / blocked，竖持停止传音后长按 A 进入。USB `tap on` 和轴设置仅对当前启动有效，重启恢复默认；按键本身仍执行原功能。

## 手持测试操作

使用 [采样脚本](../scripts/diagnose-double-tap.py)，关闭其他串口监视器。每次使用新的输出目录，保留日志和 JSON；脚本不会刷机或发快捷键，结束后回到 `tap auto`。

```sh
# 每轮提示后只双敲一次，随后等待；握法与位置保持一致。
python3 scripts/diagnose-double-tap.py /dev/cu.usbmodem1401 \
  --trials 30 --label right-hand-inverted-front-above-a \
  --output-dir artifacts/tap-trials/right-inverted-01

# 负样本示例：按正常使用方式拿起、放下、按键；不要有意双敲。
python3 scripts/diagnose-double-tap.py /dev/cu.usbmodem1401 \
  --negative-seconds 300 --label pickup-putdown-buttons \
  --output-dir artifacts/tap-trials/negative-01
```

按正常竖持、倒置对讲机握姿、左右手分别采样，先找到自然的敲击面与检测轴；Z 不合适再用 `--axis x/y`。每组 30 次，每个 3 秒提示窗口做一次双敲；窗口命中率仅在操作者确实完成每次动作时有效。保存原始命中率、过滤后命中率、额外报告数；漏做动作需要注明或重测，不能当成算法漏报。

负样本分别覆盖按 A/B、拾放、换握、走路、USB 线牵引、桌面碰撞、单敲与三连敲。分别看 raw 与 accepted，不能用场景拦截掩盖原始算法误报。最终再加 `--voice-only` 测真实对讲机场景，包含传音、退出/重进和按住 A/B 后的抑制。

继续门槛沿用迁移计划：至少一种自然握法的 30 次双敲命中 ≥95%，重复报告和延迟可接受；累计约 30 分钟有标签负样本无 accepted 误触，并检查机身敲击进入麦克风的声音。此为原型门槛，不代表长期可靠性保证。

## 尚待人工验证与下一阶段

### 第一轮手持结果与第二版诊断

用户已确认正常对讲握姿，并完成 30 组机身背面双敲。第一版参数为 Z 轴、灵敏度 9、用户滤波数据源、400 ms 窗口。105 秒采集区间中双敲 raw=0、accepted=0、blocked=0、unknown=0、错误=0，记录到倒置姿态、机身运动及正常传音。**此轮为 0/30，未通过；不是软件场景过滤造成漏报。** 逐次动作没有独立时间标签，保留的是用户报告的尝试总数与完整串口记录。

证据在 `artifacts/legacy-double-tap-v0.4.42/positive-confirmed-walkie-grip-back.json` 和 `handheld-live.log`。更早的平放采集区间没有实际完成动作，不纳入这 30 次结果。

后续 `v0.4.42-legacy-diag2` 增加：

- tap 启用/关闭后直接读取 page 5，核实只有 double tap 位开启。
- `tap sens 0..15`：灵敏度系数越小越敏感，默认仍为 9。
- `tap internal` / `tap user`：切换内部未滤波 200 Hz 数据与应用加速度数据，默认保留 user，便于对照。
- `tap dump`：直接读取启用标志、检测参数、加速度/陀螺仪配置、内部状态、中断映射及电源状态。
- 即使某次原始数据读取失败，仍处理本次已读出的 feature 状态，避免诊断事件被丢弃。

实际 SDK 的 24 组灵敏度/源/轴组合、参数读回和仅双敲启用通过 ASan/UBSan。下一轮先保留 Z/9，仅切 internal 做 5 组；若仍不触发，再降低阈值，随后才对比其他轴。每次只变更一个参数并保存结果，避免反复要求整轮 30 次。

第二版已编译安装，应用大小 1,780,208 B，静态 RAM 106,664 B；完整固件回归与 Swift 91 例通过（1 例既有跳过），Base 回退配置也编译成功。安装前再次完整备份，活动应用槽以外 Flash 与备份一致。证据在 `artifacts/legacy-double-tap-v0.4.42/diag2/`。

设备实际读回：user 源 flags=`0x004a`，internal 源 flags=`0x0042`，均仅开启双敲；加速度 `a9/02`、陀螺仪 `e8/00`、内部状态 `01`、INT1 feature map=`08`、电源 `06`，窗口/安静期均 80 个 5 ms 样本，wait=1，axis=2，sensitivity=9。由此确认第一轮采用的启用/映射/基本配置成立；第一轮 0/30 的具体原因仍待参数对照确认。

第二版小样本：背面 Z/9/internal 5 组期间报告 1 次；背面 Z/3、X/3、Y/3 各 5 组均 0 次。用户明确目标位置后，在正面 A 键上方按 Z/9/internal 再测 5 组，报告 0 次。所有阶段错误及 unknown 均为 0。由于没有逐动作标签，以上记录为尝试组数与期间报告数，不推断那唯一事件必然对应某一组敲击，也不汇总为目标位置识别率。

### 第三版原始波形诊断

`v0.4.42-legacy-diag3` 增加临时加速度 FIFO 采集：200 Hz、±8g、滤波后的传感器坐标原始 16 位数值，单次最多 60 秒（PSRAM 按需分配 72 KB）。只临时配置 accel-only/headerless FIFO，不改主采样量程、姿态坐标、tap 参数、中断路由或电源配置。停止/取消/睡眠前恢复原 FIFO 寄存器；已有 FIFO 消费者时拒绝接管。

`tap record` 开始，`tap finish` 停止并恢复，`tap wave` 查看样本数/溢出/恢复结果，`tap export` 在语音停止后分批导出 `TCWAVE` 行。录制中拒绝改检测参数，导出时若进入语音/OTA/休眠准备则取消。波形为应用滤波数据，不宣称与片上 tap 内部未滤波输入完全相同；FIFO 溢出或丢帧的记录不能当作均匀连续波形分析。

原生测试覆盖 FIFO 配置与恢复、9 个瞬时故障点、占用拒绝，以及实际 SDK 对有符号加速度极值的 headerless 解码。实机短录已获得 1,780 个样本，溢出=0、恢复=1，随后睡眠准备/撤销及新鲜采样恢复正常。第三版应用 1,784,960 B，仍保留 Base 回退；暂未接上位机映射。

第三版安装前，由已完整读取并验证的第二版前快照、已写入的第二版镜像和擦除扇区尾部重建当前快照；安装器在写入前要求设备端逐区域 MD5 全部匹配，随后仅更新活动应用槽。配对、校准、分区表、OTA 数据和备用槽验证不变。38 个固件原生测试程序、SDK ASan/UBSan、5 个电池脚本用例及 Swift 91 例通过（1 例既有跳过），Base 构建通过。

#### 正面 A 键上方的实测结论

| 参数/场景 | 用户报告动作 | 区间内 raw / accepted | 结论 |
| --- | --- | --- | --- |
| Z / internal / 系数 9，第二版 | 5 组双敲 | 0 / 0 | 未通过 |
| 同参数，第三版带 FIFO 记录 | 报告完成 3 组，保留连续波形 | 0 / 0 | 检测器未报告；波形存在多段成对冲击，实际组数不以离线峰数替代用户标签 |
| Z / internal / 系数 0，第三版 | 5 组双敲 | 2 / 2 | 阈值降低后有改善，仍未通过 |
| 同系数 0，换握/拿起/轻放，不有意双敲、不按 A/B | 用户约 1 分钟动作，记录区间约 89 秒 | 0 / 0 | 短时负样本；不能推断长期误触率 |

连续波形为 5,798 样本 / 28.99 秒，FIFO 溢出=0、恢复=1，完整导出并核对索引连续。传感器 Z 原始范围约 −0.8855 至 +0.4812g，峰峰值约 1.3667g，明显大于 X/Y 的峰峰值；Z 轴选择有实测支持。若用 205 ms 均值去除重力/慢变化，多个强冲击呈约 230–265 ms 成对间隔，并带有约百毫秒回弹。该离线处理不是 Bosch 内部算法；内部 tap 使用未滤波数据，本波形为滤波数据，不能由此精确复原芯片的所有判据。

这是“尝试组数与期间报告数”，没有逐组标签，**不宣称系数 0 已达到可靠的 40% 识别率，也不以 89 秒零报告证明低误触**。官方 AN002 的灵敏度字段为额外阈值增量系数；峰值不对称可能让系数 9 对较弱方向过严，此为推断。系数 0 的 2 次报告说明阈值有影响，尚不足以解释所有漏报。目标位置这轮仍不具备产品化条件，不进入协议/上位机映射。

证据位于本机 `artifacts/legacy-double-tap-v0.4.42/diag3/`：`front-above-a-wave.csv`、`front-above-a-wave.png`、`wave-analysis.json`、`positive-front-above-a-z-s0-internal.json` 与 `negative-front-s0-pickup-putdown-regrip.json`。前一版目标位置记录在 `diag2/positive-front-above-a-z-s9-internal.json`。完整采样、主循环最大间隔与 I²C 错误数在 `handheld-live.log`；本轮错误数和 unknown 均为 0。

实验结束恢复 Z / user / 系数 9 默认参数及 voice-only 诊断模式，停止 USB 采集。后续建议以这些实际波形做更精细的片上参数分析，或增加软件双敲识别进行对照，再使用独立、带逐组标签的正负样本验证；不继续以无标签的重复敲击盲调。实际断电拿起唤醒仍待单独人工验收。

可用参数下的真实手持命中率、上述动作误触、语音敲击噪声、完整姿态六面/转轴、实际断电与拿起唤醒、唤醒后再次双敲仍待完成。实际休眠测试需开启既有深睡设置、按原流程以电池供电进入休眠，再拿起确认唤醒、重连和双敲恢复；寄存器 prepare/rollback 通过不能替代物理唤醒。

通过这些门槛后才开发双敲协议事件及上位机映射。当前实现没有以 A/B 事件伪装双敲，也没有修改或重建 Mac 应用。
