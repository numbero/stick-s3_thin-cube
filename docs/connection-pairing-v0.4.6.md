## 改动

连接明确分为信道和设备授权两个阶段。信道及设备身份检查通过后，先尝试复用已保存授权；需要配对时自动显示“完成设备配对”窗口，包含设备名、实际连接方式、六位 PAIR PIN 输入及取消按钮。输入框自动聚焦，接受前导零，只有六位 ASCII 数字可提交；回车提交、Esc 取消。后台连接不会抢前台焦点，回到 ThinCube 后自动展示窗口，页面及菜单栏也提供醒目的“完成配对…”入口。

提交期间保留同一个窗口，禁止重复提交；错误码在窗口内显示并重新聚焦。配对码验证后仍等待有效控制会话，收到设备状态才关闭窗口并报告连接成功。取消会取消本次授权等待、关闭信道并停止自动重连；连接代次检查拒绝旧请求的晚到响应。

A+B 的 RE-PAIR 提示及 PAIR PIN 页面使用当前实际连接方式。根因是原提示复用了长按 B 的“切换目标”计算：所有非切换中场景都取当前方式的相反值，导致 BLE 重新配对显示 WI-FI；实际配对逻辑没有切换方式。现在只有单 B 切换提示取相反方式，A+B 保持当前方式；已受理的切换仍显示受理目标。同时调整 240×135 横屏的提示坐标，避免沿用竖屏坐标造成文字越界。

设备列表按身份合并 Wi-Fi / 蓝牙发现结果，并区分“当前连接”“已发现”和“上次选择 · 暂未发现”。系统“忽略”撤销的是系统绑定，仍在广播的设备继续可发现；ThinCube 的应用授权独立保存。未发现的历史选择不再冒充在线发现结果。过期的蓝牙发现同时清理无活动连接的 peripheral 缓存；正在建立信道或当前连接不会被发现过期清理中断。

蓝牙加密及绑定保持原有实现。首次系统确认可能仍需点击“配对”，上位机显示明确引导，并将加密服务就绪等待延长至 90 秒；用户取消或等待超时后停止本次自动尝试，避免连续弹出确认。有效系统绑定和应用授权继续自动复用。公开 API 与本机只读可行性探针结论见 [蓝牙确认自动化调研](bluetooth-automation-research.md)：目前没有可靠公开桥接可接管现有 CoreBluetooth 的无数字系统配对窗口，因此没有加入系统窗口自动点击代码。

## 重新配对松键即退出修复 v0.4.36

这两次修复的版本、镜像校验、自动检查、配置保留及用户实机确认另存为[可跟踪验证摘要](validation/re-pairing-v0.4.36-v0.4.37.json)。固件镜像、Flash/NVS 备份及原始日志保留在本机忽略目录。

2026-10-17，修复正常运行时 A+B 长按三秒、松开后立即返回主界面的问题。按住时显示的 `RE-PAIR / release A + B` 是手势确认提示；两键松开后应显示 `PAIR PIN`，保持两分钟，直到配对成功、B 取消或超时。

根因：`loop()` 在 `uiTick()` 前采集时间，松键操作在 `deviceOpenPairing()` 内用较新的 `millis()` 开启窗口；随后 `deviceTick()` 用本轮较旧的时间计算超时，无符号相减下溢，窗口被立即判为过期。A 刷新码及 HTTP 开启窗口同样可能遇到这个时序。

超时检查改为取得配对锁后读取当前 `millis()`；配对窗口策略用有符号时间差容忍同轮稍早的采样，保留正常计时回绕。网络、连接方式、旧授权保留及成功后替换授权的规则继续沿用。

新增回归测试在修复前稳定触发断言失败，修复后通过。覆盖同时松键、先松 A、先松 B，分别叠加 1 / 5 / 100 毫秒采样差；检查松键不会触发单键动作，窗口在到期前保持、恰好两分钟关闭，并覆盖刷新、取消、首次配对等待及 `millis()` 回绕。全部 32 个固件 C++ 测试程序通过，新增测试也通过 C++11 编译；PlatformIO release 和 Mac 端真实镜像身份校验通过。本轮未重建 macOS 应用。

## 重新配对后 Wi-Fi 控制会话残留修复 v0.4.37

用户反馈：设备右上角 Mac 图标灰色、显示等待宿主机，但 Mac 仍显示在线且姿态持续更新。

原因是 `deviceOpenPairing()` 停止语音、重置控制心跳并将 `owner` 设为 -1，却只断开 BLE，没有关闭原 Wi-Fi WebSocket。旧连接的心跳因不再属于 owner 而被忽略，但 HTTP 处理器仍逐帧返回状态快照；Mac 因为持续收到有效状态而保持在线。因而此时设备确实没有有效控制会话，姿态更新不能证明控制或语音通道仍可使用。取消或超时保留旧授权后，遗留的 WebSocket 也不会自动重新取得控制权。

v0.4.37 在开启配对窗口、使旧授权暂不可用之后，通过 HTTP server 的 `httpd_sess_trigger_close()` 异步关闭原 Wi-Fi 控制连接；BLE 继续沿用原有断开流程。新的授权控制连接接管设备时也会关闭前一 Wi-Fi owner，避免旧上位机继续以状态回包误判在线。Mac 无需重建：现有断连处理释放语音及快捷键，按既有恢复策略重连；若在重新配对期间自动恢复，会明确暂停并提示让其他上位机配对。取消设备重新配对后，可在 Mac 点击“连接”恢复旧授权会话。
