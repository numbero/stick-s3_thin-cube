## 参数

| 控件 | 底层字段 / 默认 | 允许范围及含义 |
| --- | --- | --- |
| 开启检测 | 默认开启 | 关闭时仍可应用、读回参数 |
| 单 / 双 / 三敲诊断 | 对应 feature enable 位；默认仅双敲 | 可分别打开，便于发现同一动作是否被分到其他类型 |
| 数据源 | `data_reg_en=1`，应用滤波数据 | 可切内部未滤波 200 Hz；加速度固定 200 Hz / ±8g，陀螺仪 100 Hz / ±2000°/s |
| 检测轴 | `axis_sel=2` | 传感器 X / Y / Z 中选择一个；不是按机身不同面分类 |
| 灵敏度 | `tap_sens_thres=9` | 0–15，越小越敏感；阈值增量系数，不是敲击力度分类 |
| 连续敲击窗口 | `max_gest_dur=80`，400 ms | 250–1000 ms，5 ms 步进；从首次敲击开始计时 |
| 手势后安静时间 | `quite_time_after_gest=80`，400 ms | 250–500 ms，5 ms 步进 |
| 等待窗口结束分类 | `wait_for_timeout=1` | 关闭可能在同一组敲击中产生多次报告 |
| 手持实验模式 | 默认关闭 | 开启时不要求倒置传音，始终只记录；其他忙碌/按键保护保留 |
| 进入场景稳定期 | 默认 500 ms | 0–5000 ms |
| A/B 按键后抑制 | 默认 500 ms | 0–5000 ms；按住始终拦截，与场景稳定期分别计时 |
| 接受双敲后冷却 | 默认 600 ms | 0–10000 ms |

以上六个原生配置字段均经官方 SDK 写入与读回，并验证所选 feature enable 位。SDK `bmi2_tap_config` 中的 `tap_shock_dur` / `min_const_thres` **在固定 Legacy 驱动里没有 getter/setter 实现**，界面明确说明不可调节，不写保留寄存器，也不展示伪生效控件。[Bosch Legacy 官方说明，第 36、69–71 页](https://www.bosch-sensortec.com/media/boschsensortec/downloads/application_notes_1/bst-bmi270-an002-01.pdf)。

## 识别与试次

- 芯片双敲 `raw`、过滤后 `accepted`、被拦截 `blocked` 分开显示，单敲、三敲和未分类另行计数。单/三敲不进入双敲接受计数。
- 显示场景、按键、稳定/按键抑制、冷却的拦截计数，最近双敲事件序号、设备时间、结果，以及健康、I²C 累计错误、最大轮询间隔。
- A/B 按住、配对/配网、OTA、切换连接、横屏游戏、休息、休眠准备及 IMU 失效不接受事件。手持实验模式只放宽倒置传音要求并禁止发键。`accepted` 是检测准入；只有所选来源、正常传音场景及已协商的新上位机才可进入手势队列。上位机还须有对应映射才会注入。
- 上位机仅保留调参和实时计数，不再要求操作者开始/结束每个试次或导出文件。
- 代理运行 `scripts/sample-double-tap.py`，自动配置及读回，通过 Mac 中文语音提示分组，采集正/负样本，保留完整 JSON 和串口日志，结束后自动恢复原参数。操作者只需在提示时做一次双敲，然后按提示进行日常动作。
- 自动窗口并不等于真实动作标签；结束后仍需操作者确认是否完成每组动作。不得把未做动作的窗口当作算法漏报。
- 采集期间配置版本变化、计数清零、重启、IMU 错误或健康变化会让当前区间失败，保留已采数据及错误。旧版手动采样数据仅作为历史证据保存在原产物目录。

软件对照从共享的 200 Hz 加速度 FIFO 逐样本读取，保留独立的候选、双敲、接受和拒绝计数。仅同极性冲击参与一组，回弹排除期内的强冲击仍参与计数以拒绝快速三敲。原生与软件分别统计；默认软件识别进入快捷键队列，关闭软件增强则改用原生双敲报告，两个来源不会同时发键。

软件参数全部可调：冲击阈值 100–2000 mg（默认 550）、回弹排除 80–300 ms（180）、早到冲击相对强度 40–95%（65）、分类窗口 250–1000 ms（450，必须大于回弹排除）、旋转阈值 30–600°/s（200）、旋转后抑制 100–2000 ms（300）、重力基线滤波 50–1000 ms（200）、旋转强度滤波 0–1000 ms（100，0 为原始旋转值）。原生六项配置、类型开关及共享场景/按键/冷却保护继续保留。

先对照 internal/user，再对照灵敏度；每轮只变更一项并保留独立试次。若 raw 漏报，调整片上配置；raw 有报告但 accepted 没有时先看软件拦截。双敲沿用单次按下/松开语义；映射入口为「按键 → 独立双敲」，支持选择、录制及清除。

## 通信与失败处理

已配对的 HTTP `GET /api/tap` 返回独立状态；`POST /api/tap` 使用 `action=configure/reset`、`requestId`，配置位于完整 `config` 对象。BLE 使用认证后的 `op=tap`，无 action 或 `action=status` 为查询。敲击参数保留独立缓存；full status 仅增加 `tapProtocol=1` 能力与 `tapMode` 协商状态，BLE 增量同步 `tapMode`。`gestureProtocol` 继续为 1，心跳额外发送 `tapProtocol=1` 才启用双敲事件，旧上位机不启用双敲；新上位机忽略旧固件的双甩事件。

网络回调只做校验/排队；主循环独占 I²C 操作，100 ms 发布敲击缓存。上位机仅在调试页打开时每 500 ms 查询，关闭页面停止。`accepted=true` 仅表示入队，上位机须等待匹配 requestId 的 `result=ok`、verified 和实际配置才报告成功。读取失败时禁用编辑并标记过期，不把旧值当实时数据。

配置有严格类型、范围和 5 ms 网格校验。写入失败时完整恢复并读回旧参数；恢复失败则停止软件接受并标记未验证。睡前关闭检测，取消睡眠后恢复当前参数。USB 旧诊断命令及原有日志格式保留；新增 `tap json` 状态与 `tap apply <JSON>`，复用网络接口的校验和主循环写入/读回。USB 最大行长 768 字节，溢出整行丢弃，避免执行截断命令。

## 2026-10-19 自动实测与定位

- v0.4.51：操作者确认 10 组均各双敲一次。原生总计报告 9 次；首组语音启动延迟导致窗口跨组，不能把下一组的两次报告当成一次动作重复。已修正自动脚本为语音完成后保留完整动作时间。60 秒日常动作原生双敲 0 次。
- v0.4.51：后续五个提示窗口录到两次明显冲击，原生只报 1 次。该波形支持 200 Hz 软件对照的开发；100 Hz 降采样会丢较弱峰。
- v0.4.52：10 个提示窗口原生报告 8 次，软件 0 次。60 秒日常动作两者均 0。未据此宣称算法有效。
- v0.4.53：操作者明确确认 3 组均完成。原生报告 2 次；软件每组均有候选，但均因旋转拒绝，I²C 错误 0。同步记录的敲击中陀螺仪强度最高约 400°/s；默认 150°/s 保护过严。相同代码与实际加速度/陀螺仪输入回放：150°/s 得到 0 次，450°/s 得到 3 次，已有单甩、双甩和自然晃动记录仍为 0 次。原参数随后 30 秒日常动作零报告。

以上三个正样本用于调参，450°/s 的 3/3 为回放结果，不能当作独立实测准确率。完整数据和固件安装校验保存在 `artifacts/double-tap-comparison-v0.4.53/`。自动脚本支持 `--trials 0 --wave-negative` 单独补采日常动作，波形最多 60 秒；所有参数仅运行时修改并在结束时恢复。

## 旋转保护的独立验证与修正

随后将旋转阈值改为 450°/s：新采集的 60 秒日常动作产生两次软件误报，原生为零；提高冲击门槛至 550 mg 后，校准数据回放零误报。再用 550 mg / 450°/s 独立采集：三个新双敲窗口均报告一次，但另 60 秒日常动作仍产生一次软件误报，因此没有接入发键。该次正负波形在 `auto3-validation550/`，已保留为回归数据。

逐样本旋转阈值无法区分敲击瞬间振动与持续换握。v0.4.54 增加 `softGyroFilterMs`（0–1000 ms，0 为原始旋转值），对旋转模长进行因果低通后再执行保护，原始值仍保留为诊断与波形输入。候选参数为冲击 550 mg、旋转 200°/s、旋转滤波 100 ms，其余保持原值。相同 C++ 检测器回放前述六个带陀螺仪正样本窗口均识别一次，两段各 60 秒日常动作均零报告，已有三类甩动记录也为零。单个陀螺仪尖峰不再拒绝一组双敲，持续旋转仍拒绝；两个行为均有独立合成回归。新参数尚需设备实测验收，仍不以回放代替实时识别。

## 最终实时验收与映射

v0.4.54 使用 550 mg / 200°/s / 100 ms 旋转滤波，另采三个双敲正样本及 60 秒拾放、换握、短按键负样本。操作者确认三组均各完成一次，负样本期间无有意双敲；设备三个窗口均软件报告一次且接受一次，负样本软件与原生双敲均为零，健康及读回持续有效、I²C 错误为零，结束后成功恢复参数。原始记录位于 `artifacts/double-tap-filter-v0.4.54/auto1-validation/`。这是本机自然握姿的小样本结果，不能推导总体识别率或所有握姿下无误触。

v0.4.55 / Mac v0.4.23 在上述验收后接入独立 `double_tap` 事件。事件与双甩共用单调序号、4 项队列、750 ms 有效期和精确确认；新场景、断线、模式变化、过期及编辑中的事件丢弃，不补发。Mac 为双敲使用独立保存键 `shortcut.double_tap.<device>`，原 A/B/双甩键不迁移。一次双敲只构造一组完整按下与松开；不会保留长按状态或释放 A/B 所拥有的按键。

调参面板打开期间，Mac 确认并丢弃双敲，不影响双甩；关闭后仍丢弃 750 ms 内的旧双敲。手持实验模式在固件端禁止双敲入队，因此自动采样不会触发已绑定的快捷键。默认没有双敲绑定，没有替操作者选择或注入任何键。最终映射包括队列类型、混合事件去重、BLE 协商合并、独立存储及完整松键回归；实际目标应用的按键效果需使用操作者自行设置的绑定。

最终安装核验：Mac 0.4.23 build 44 已替换 `/Applications/ThinCube.app` 并通过固定签名身份校验；按键页实际显示原 A/B/双甩绑定及未绑定的独立双敲。设备 6046E5 已更新 v0.4.55、app0，备份及分区外哈希确认 NVS、OTA 元数据和其他闪存均未变。两次开机只读检查默认增强参数及健康有效；连接检查 45.068 秒采集 9026 个 FIFO 样本（200.28 Hz），I²C 错误为零，观察到 `[gesture-mode] flick=1 tap=1`。两个固件环境构建通过，本地 CPU / Bosch SDK sanitizer / Python 回归通过，Swift 103 项（1 项已有跳过）无失败。证据位于 `artifacts/double-tap-shortcut-v0.4.55/`。

## v0.4.56：移除双甩

按用户要求移除固件双甩检测器、采样导出和 USB 命令、轮询与诊断显示及专用构建环境；手势队列只承载 `double_tap`。Mac v0.4.24 移除双甩枚举、映射、测试按钮、帮助文案及存储读写，启动时删除旧 `shortcut.double_flick.*` 绑定，不迁移到双敲，不改 A/B 或已有双敲绑定。新客户端仅在设备宣告双敲能力时协商手势，收到旧双甩事件时确认并丢弃，不注入键盘事件。

双敲算法、550 mg / 200°/s / 100 ms 旋转滤波默认值及全部调参项保持不变。原始甩动录波仅留作双敲误触回归的负样本，不包含旧识别器或入口；历史版本文档标记为已移除。

移除版验收：两个固件环境构建通过，CPU / Bosch SDK sanitizer / Python 回归及 Swift 103 项（1 项已有跳过）无失败；固件镜像不含旧 `double_flick`、`[flick-`、`TCFLICK` 字符串。Mac 已实际安装到 `/Applications/ThinCube.app`，界面仅 A/B/独立双敲；清理 1 个旧双甩绑定，其余 5 项快捷键配置哈希逐项不变。设备 app0 已更新 v0.4.56，NVS、OTA 元数据和活动槽外 Flash 校验未变。开机检查双敲参数有效、FIFO 200.3 Hz、传感器错误 0，已协商 `tap=1`。证据保存在 `artifacts/remove-double-flick-v0.4.56/`。
