# ThinCube 在线省电与可选深睡 v0.4.18

实施日期：2026-10-14。用户授权实施“默认在线省电＋可选深睡待机”。继续保留电压分段显示与无前缀百分比，不进行充放电、电流或实际容量实测。

## 默认行为

深睡默认关闭，原30秒视觉睡眠、5分钟息屏、10分钟纯电池物理关机规则保留。启动健康确认完成（至少60秒运行）、视觉睡眠稳定且没有游戏、音效、配对、配网、OTA、旋转、传音或传感器失效时，CPU降至160MHz；唤醒、麦克风和扬声器启动前恢复240MHz。闲置绘制改为5fps，IMU轮询最多25Hz，完整状态JSON重建最多5Hz；命令和配置变化立即重建。200ms BLE快速状态与心跳、400ms Mac失效保护、1秒语音租约保持。

BLE待机请求60–90ms、latency=0，恢复请求15–22.5ms；Mac实际协商结果记录在 `power.bleInterval`（单位1.25ms），最多30ms作为可传音的快速连接容差。请求超时或拒绝后禁用本连接的再次闲置请求，恢复快速模式。新的语音开始必须有已确认的快速连接；手动开始可保留最多5秒的新请求，取消、失联、禁用或静音会清除，不直接在慢连接中发送开头音频。CPU和连接参数的切换不改变原有录音采样率。

BLE控制器尝试启用Modem-sleep，使用主晶振作为睡眠时钟；初始化/启用不支持时，清理控制器后退回原配置。没有启用需要重建SDK的自动Light-sleep，也没有把普通 `delay` 当作硬件睡眠。[IDF无线睡眠说明](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32s3/api-reference/system/sleep_modes.html#wifi-bt-and-sleep-modes)

## 深睡待机开关

Mac“设备 → 设备设置”新增“深睡待机”。设备确认保存后才更新开关，默认关闭、旧固件不提供时不可用。开启后，纯电池供电且静置5分钟进入PM1 L1：主控断电，仅保留IMU及所需电源/唤醒输入；拿起或机身电源键唤醒后重新初始化并自动认证重连。USB、未知供电、无效电量或低压提醒时不进入该模式。A/B和Mac指令不能唤醒已经断电的主控；要完全关机，先唤醒并关闭此开关。

睡前以当前认证epoch发布 `sleep={id,phase:"preparing"}`。Mac释放快捷键和音频缓冲后发送 `sleep_ack`，带同一epoch及sleepId；已连接却2秒没有确认，或发生新活动、指令、连接丢失、供电变化，会取消并重新给予空闲窗口。原本离线时不要求Mac确认，但仍有350ms准备窗口；准备时新增连接必须确认。OTA与切换共用电源准入锁，等待睡眠确认期间拒绝OTA开始。

Mac仅将5秒内已确认的睡眠通知之后的断连视为预期深睡，普通失联仍走故障保护。取消通知、新会话和重新连接清理旧状态；原配对、设置和自动恢复保留。

## 传感器与电源事务

复用现有M5Unified加载的Bosch base BMI270配置，无新增feature blob。ANY_MOTION page1/offset0x0C，三轴、100ms、约83mg，50Hz低功耗加速度；INT1低有效、非锁存，关闭陀螺仪、温度及普通数据中断。启用PM1 GPIO4下降沿唤醒，仅保持LDO与GPIO4，关闭5V boost及其他HOLD。这些是官方参数起点，没有声称已标定本机拿起阈值。[接口核查](sticks3-deep-sleep-research-2026-10-13.md)

准备前保存普通寄存器与feature页；读写均检查返回状态和配置读回，最终要求唤醒线连续HIGH、BMI内部状态正常，以及重新确认纯电池供电。任何失败先关闭运动唤醒/HOLD，再尝试所有恢复动作；无法确认APS已关闭时不做feature burst写，恢复失败时重新初始化普通IMU并禁用深睡。只有准备全部成功才发PM1关机命令；若命令返回后主控仍运行，恢复在线，不进入没有唤醒源的ESP睡眠。

每次启动清除残留GPIO4唤醒、LDO/GPIO4 HOLD及醒因；普通十分钟关机前也解除运动唤醒，避免设置在后续关机中残留。硬件欠压保护、充电配置和配对NVS不重置。睡着时CPU已经断电，无法通过应用代码拦截机身双击来解除运动唤醒，这一限制已写在开关说明中。
