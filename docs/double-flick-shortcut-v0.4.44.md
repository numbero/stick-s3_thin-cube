# 连续双甩快捷键：设备 v0.4.44 / Mac v0.4.17

2026-10-18，按用户要求将双甩原型接成正式快捷键输入。沿用已实测的 diag3 双脉冲参数，新增独立映射；每次识别执行一组按下与松开。

## 使用方式

ThinCube 的“按键”页新增“连续双甩”，支持录制、选择和清除快捷键，按设备保存，默认未设置。左右修饰键设置与 A/B 共用。连接旧固件时该行禁用；原 A/B 配置无需迁移。

| 输入 | 对讲机状态中的行为 |
| --- | --- |
| A | 按下保持，松开释放 |
| B | 按下保持，松开释放；未设置时不执行 |
| 连续双甩 | 两次方向相近的强甩动，最后收回停稳；识别一次，按下并松开一次；未设置时不执行 |

双甩只在正在传音、倒置对讲姿态、控制心跳有效、未静音且 A/B 均松开时识别；配网/配对、OTA、信道切换、休眠、电量校准与横屏游戏均排除。姿态、A/B 与休眠路径沿用已有实现。

## 事件与执行

- 双甩使用独立 `gestureProtocol=1`，不伪装成 A/B 保持状态。客户端心跳发送 `gestureProtocol` 和 `gestureAck`，原 `keyProtocol=2` / `ack` 保留。
- 完整状态宣告 `gestureProtocol`，协商状态为 `gestureMode`。事件为 `gesture:{seq,type:"double_flick",ageMs}`，无事件为 `null`。Wi-Fi 与 BLE 均支持；新协议 BLE 增量必须显式携带该字段，防止保留旧事件。
- 设备采用容量 4 的队列，750 ms 到期，只有匹配队首的确认才出队，序号跳过 0。停止对讲、断线、按下 A/B、切换协商或重建控制会话时清空待发事件。
- 上位机按 epoch/序号去重。进入新上下文、过期、未配置、编辑、测试、停止或禁用时，确认并丢弃，不在解除限制后补放。编辑完成后另留 750 ms 窗口丢弃旧动作。
- 先构造完整系统按下/松开事件，再一次提交，不依赖下一包或延迟任务松键。共用 A/B 的键盘所有权计划器，保留其他输入及物理键盘持有的修饰键；主键被占用时整组拒绝。

该通道会丢弃过期输入，避免重放；不承诺断连或应用崩溃时仍交付事件。

## 构建与安装

正式默认环境 `m5stack-sticks3` 采用 Legacy 后端，启用 `THINCUBE_FLICK_SHORTCUT`、关闭 tap。原 Base 保留为 `m5stack-sticks3-base`；原诊断环境保留，诊断镜像不宣告正式事件能力。参数及历史见 [双甩原型](double-flick-prototype-v0.4.43.md)。

Mac 经 `scripts/build-macos.sh` 构建、稳定签名、替换 `/Applications/ThinCube.app` 并重启，版本 0.4.17、构建号 38。旧应用备份保存在 `artifacts/install-backups/`。

USB 更新 ThinCube-6046E5（MAC `7c:e8:b1:e5:46:60`）app0。写入前验证完整备份，写入后核对镜像、全部程序槽外 Flash 及分区表/NVS/OTA 元数据，原配对、校准、设置和备用镜像保持一致。镜像 1,791,056 字节，SHA-256 `999376d6aaff2a114e0465b22c2d7f643b29db7b1d81439f23254ca27207b4ae`。

- 原型实测为 5 组双甩/5 次事件、4 次有效单甩/0 次事件、约 1 分钟日常动作/0 次事件，属于小样本；正式版参数保持不变，新增映射与传输。
