# 对讲机 B 键快捷键 v0.4.41

日期：2026-10-18。固件 v0.4.41，Mac v0.4.16（build 37）。Mac 已安装到 `/Applications/ThinCube.app`，设备固件已通过 USB 安装，启动及原配对恢复正常。用户完成 BLE 实体按键验收并确认“已完成，行为正常”；临时 F18 映射已清除，原 A 右 Command 设置保留。

## 使用行为

- 仅在现有 A 快捷键可用的倒置对讲机状态中，B 才是第二枚自定义快捷键：已传音、连接及采集就绪、竖屏、没有游戏占用。自然倾斜沿用已有 v0.4.40 姿态容错，不改变姿态参数。
- A/B 各自按下保持、松开释放，可同时按住。B 在此状态不静音，长按不切换 Wi-Fi/BLE，A+B 不重新配对。
- A/B 沿用当前统一的念力对讲机动画：任一按住时抬机并显示绿灯，两枚都松开后回待命动作。2026-10-18 用户在调研后明确选择保留此行为，暂不采用差异化动画；角色绘制代码没有改动。
- 普通模式 B 继续短按静音、长按约 3 秒松手切换连接方式；配对、OTA、启动恢复出厂等系统页面保留原操作。
- 按下时已经属于对讲机的 B，不会在模式退出后的松手被重新解释为静音、切换或配对。进入对讲机前已按住的 A/B，分别需要先松开再按下。
- Mac 按键页新增 B 的录制、直接选择和清除；A 配置沿用原存储，B 默认未设置、此时对讲机内不执行操作。两行共用现有左右修饰键开关，组合按设备分别保存。
- 诊断区分别显示 A/B 状态、来源与本窗口注入测试。系统事件已提交不能证明目标语音软件已经处理。

## 协议兼容

完整状态新增 `keyProtocol:2`、当前 `keyMode:1|2` 和 `heldB`。旧的 `held` 继续表示 A，BLE 原 flags 位布局不变；快速状态额外传 `keyMode`、`heldB`。

新 Mac 发现能力后在原鉴权控制心跳中发送 `keyProtocol:2`。设备仅对当前 owner 和 epoch 处理协商，确认后报告 `keyMode:2`，事件增加来源：

```json
{"edge":{"seq":12,"down":true,"key":"b"},"keyMode":2,"heldB":true}
```

A/B 共享 32 项可靠有序队列和既有 `ack`，一次只确认队首。每个新边沿执行一次，重传、重复及倒序旧边沿不会重复执行；仍处理 UInt32 回绕。无绑定、编辑期间或其他受阻事件照常确认，不在恢复后重放。

未协商时维持原 A-only 事件和 B 功能；旧 Mac 不会收到伪装成 A 的 B 事件。新 Mac 连接旧固件时仅 A 可用，B 行提示升级。新控制连接重置协商及队列；新语音会话清除旧队列。Mac 在 epoch、语音 session 或协商模式变化时先释放全部组合。

## 按键所有权与清理

固件用物理按键的真实状态决定进入时是否需要重新武装，UI 暂时屏蔽 A 不代表物理松开。按键路由消费 B 的完整操作周期，避免短按/长按在模式边界泄漏到系统动作。

Mac 用同一注入器按 A/B 保存所需键，合成按键由共享所有权管理。例如 A 为 Command+A、B 为 Command+B，松开 A 只释放 A 主键，Command 直到 B 松开才释放；相同组合也只在最后一个来源松开时释放。保留真实键盘冲突检查和左右修饰键 flags。

停止、静音、断线、锁屏、睡眠、升级、编辑及退出应用沿用原全释放路径；设备状态超过 400 ms 未更新时释放全部来源。协议确认与当前 `held/heldB` 快照不替代可靠边沿。
