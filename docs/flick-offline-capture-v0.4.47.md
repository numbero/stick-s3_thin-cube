# 自然双甩的拔线采样与 USB 导出 v0.4.47

2026-10-18。用户反馈双甩需要用力，要求用 5 组自然幅度检查原因。最终按用户指定流程：USB 烧写、拔线采样、通知插线、USB 回传；不使用无线导出、不访问配对钥匙串、不做新的整片备份。

## 采集流程

实际连接串口需要安装 `pyserial`；数据解析测试只使用 Python 标准库，不访问硬件。

```sh
python3 scripts/diagnose-flick-offline.py --output-dir artifacts/flick-natural-v0.4.47
```

1. USB 连接、设备正面朝上、不按 A/B，输入 `record LABEL`。确认固件报告采集已启动后，脚本关闭串口。
2. 拔掉线，回到正常对讲握姿，确认传音恢复，使用自然幅度完成 5 组双甩，组间停至少 3 秒。无需刻意加力或加速。
3. 完成后正面朝上放平、停止对讲，再插 USB。输入 `export 5` 冻结并导出 CSV；`quit` 退出脚本。

设备在 PSRAM 保存最多 6000 个新陀螺仪快照，60 秒后或缓冲区满时冻结，不覆盖。快照包含时间、加速度 g、角速度 °/s、有效对讲/按键/传感器健康标志，以及识别阶段、事件和拒绝原因。`flags=5` 表示有效对讲且传感器健康；事件 3 为识别、4 为拒绝，其他枚举顺序见 `FlickDetector`。它是主循环快照，不是连续 FIFO 数据。

采样不写 Flash，不改 IMU 配置或识别参数。Wi-Fi/BLE 只继续原来的控制与语音，不传诊断波形。v0.4.46 曾安装过无线诊断入口，用户明确改为有线后，v0.4.47 已移除该入口与客户端。

## USB 连线与完整性

此前串口使用 DTR/RTS 均低的配置，打开时可能触发 ESP32-S3 USB/JTAG 复位。本脚本改为两条控制线均高，并清除 `HUPCL`，避免关闭端口时挂断。实机连续两次开关串口，设备运行时间为 422700、423504 ms，均未复位。实际拔线再插线的数据保留仍通过本轮样本验证，不把软件开关串口等同于物理插拔。

`flick record` 开始；`flick finish` 冻结；`flick samples` 报告段 ID、起始时间、计数和最大间隔；`flick export` 分批输出，单个主循环最多 8 个样本。导出要求采集停止且没有传音。每行带序号，开始/结束帧带同一段 ID 和总数。脚本核对与开始时的 ID/起始时间一致、全部行连续、数值有限且时间顺序有效后才保存 CSV，检测到启动日志或中断不会将其当作有效样本。导出不清除 RAM，可在失败后重试；重启或断电仍会清空内存。
