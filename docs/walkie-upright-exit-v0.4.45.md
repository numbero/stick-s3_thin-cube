# 对讲机翻回正立的响应 v0.4.45

2026-10-18。针对手持对讲后翻回正常竖持，长时间不能退出的问题。代码、测试、固件构建与 USB 安装完成，3 次实机切换通过，用户确认明显变快。本次未修改或重建 macOS 上位机。

## 原因与调整

v0.4.44 沿用此前为避免说话时倾斜断音而收紧的规则：所有普通退出姿态都必须进入距目标轴约 15° 的范围，并连续保持 450 ms。手持正立仍有一点偏斜时，可能始终未进入确认范围；临界角度的抖动又会重新计时。该时间不是从开始翻转就计算。

v0.4.45 将翻回正立单独处理。设备必须已经从倒立跨过水平，来到相反的正常竖持方向，才适用新的快速退出。

| 项目 | v0.4.44 | v0.4.45 |
| --- | --- | --- |
| 正立退出的主轴进入阈值 | > 0.966，约 15° 内 | > 0.90，约 26° 内 |
| 正立候选期间的主轴保留阈值 | 同进入阈值 | > 0.85，另受原横向轴限制 |
| 正立连续确认 | 450 ms | 180 ms |
| 横持、屏幕朝上退出 | > 0.966、450 ms | 保留 |
| 倒立进入对讲 | 220 ms | 保留 |
| 屏幕朝下识别与休息 | 原识别、安静放置策略 | 保留 |

只有先进入约 26° 的范围才启动正立计时；随后的小幅偏斜允许继续计时。真正转离、切换目标、加速度不在原有效范围、角速度过高，仍重新计时。运动模糊状态仍保持对讲，短暂经过正立不会立刻退出。退出时沿用原按键释放及双甩待发事件清理路径。

180 ms 是有效姿态的连续确认时间，不是从翻转开始到画面完成的实测时延。退出后仍有原屏幕方向确认 90 ms、180° 旋转动画 180 ms，以及采样和循环调度时间。它们没有在本次修改中提速。

## 验证

- 41 个固件 C++ 测试程序、Python 电量检查、Legacy SDK ASan/UBSan 检查通过。Swift 97 项，跳过 1 项，失败 0 项。
- 姿态与语音联合测试由 11 组扩展到 15 组：覆盖两种竖向校准符号、四向正立偏斜、179/180 ms 边界、候选角度回差、真实离开后重新计时、快速旋转/异常加速度、A 键释放、显示方向交接、手动持续传音及计时回绕。原横持/平放、倾斜容错、倒扣休息、恢复与重连场景继续通过。
- 历史手持录波回放新增姿态/语音联合检查，确认正立快速退出不会中断这些样本中的对讲：5 组双甩仍为 5 次事件，3 次单甩仍为 0 次事件。录波是日志快照，不是连续 FIFO 数据，也不能代表全部使用场景。
- 正式 Legacy 固件构建通过。镜像 1,791,104 字节，SHA-256 `305978ac365f976a380083633e435b5e9af927e24e2dd7830dd40f49a1c613e0`。
- USB 安装 ThinCube-6046E5（MAC `7c:e8:b1:e5:46:60`）app0，写入前将重建备份与设备完整 Flash 分区域核对一致，写入后校验程序镜像、全部程序槽外 Flash 以及分区表/NVS/OTA 元数据，保留原配对、设置、校准和备用镜像。启动日志确认 `v0.4.45`、Legacy 六轴健康、tap 关闭、双甩正式模式启用，BLE 控制恢复。
- 用户实际完成 3 次倒立进入对讲、翻回正立退出。日志记录 3 次启动、3 次正立停止；退出确认分别为 185、195、201 ms，随后分别约 312、310、306 ms 完成屏幕旋转。此轮双甩识别事件为 0（翻转产生的 2 个候选均被上下文取消），用户确认切换明显变快。采集已停止。

固件、测试、构建及安装证据保存在 `artifacts/walkie-upright-v0.4.45/`。此次为 3 次切换的小样本体验验收，未测量从开始翻转到切换完成的总耗时；自然握持与甩动下的长期稳定性仍需后续使用观察，不将自动测试的 180 ms 边界当作端到端测量。
