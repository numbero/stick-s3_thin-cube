# ThinCube 电量估算改进方案

日期：2026-10-17。状态：设计方案，尚未实现或烧录。对象：StickS3 / M5PM1，先验证 ThinCube-6046E5，再决定是否适用于其他设备。

后续决定：用户选择直接采用M5官方换算公式并保留既有滤波/保护，本状态机方案未实施。已完成的v0.4.30实现和烧录见 [发布记录](battery-official-v0.4.30.md)。

## 目标与范围

采用“电源状态管理 + 电压估值 + 本机工况标定”，借鉴 [InfiniTime 的状态分层](https://github.com/InfiniTimeOrg/InfiniTime/blob/6c119eb52206b580b556b41633dddc1e1b66a8da/src/components/battery/BatteryController.cpp#L18)，针对 StickS3 重新定义满电与退出条件。

第一阶段解决短暂高电压被立即解释为满电、充电状态未参与展示判断的问题；第二阶段提高曲线对本机电芯和实际工况的适配程度。两阶段分别验收“显示行为”和“估计准确度”，不会以数字更平稳代替容量验证。

本轮日志显示：关机充电后开机最高 4192mV，100% 约持续十余秒；此后始终接外电，14:45:56 已读 rawMv=4044、filteredMv=4042、显示 84%，屏幕亮度 0、CPU 160MHz。该轨迹要求方案既防止过早认定满电，也继续反映持续电压下降。算法更新本身不能证明电气问题已解决。

## 一、测量、估值和展示分开

```mermaid
flowchart LR
    A[每秒采样 VBAT / VIN / 电源来源 / CHG_STAT] --> B[有效性检查与电压滤波]
    B --> C[参考或本机标定曲线]
    C --> D[电源状态与估计可信度]
    D --> E[界面百分比和充电图标]
    B --> F[低压判断与 OTA 电压门槛]
```

- **测量层**：保留现有 1Hz、七点中值和 EMA。新增记录 CHG_STAT 原始值及去抖值，失败读数用未知表示，不能变成“未充电”。记录亮度、CPU、无线及音频工况，但不据此虚构电池电流。
- **估值层**：继续输出不带显示规则的 `voltagePercent`。未标定时使用现有参考曲线并标记为参考估值；有匹配设备和工况的有效标定时才选用专用表。
- **展示层**：使用电源状态、稳定性和满电证据生成 `displayPercent`。充电图标仍对应真实测得的充电状态，外电存在和正在充电分开。
- **保护层**：低压及 OTA 决策继续直接依赖新鲜电压和原有保守规则。展示值即使较高，也不能放宽它们。

现有 `powerTick()` 在 `gauge.sample()` 之后才更新 CHG_STAT。实现时先采集这一轮所有输入并分别检查新鲜度，再提交统一快照，避免估值和充电状态相差一个更新周期。

## 二、状态与界面行为

| 状态 | 进入条件 | 百分比与退出规则 |
| --- | --- | --- |
| 初始化 / 工况切换 | 开机、可靠的供电切换，或从失效数据恢复 | 使用现有 `--%` 暂不下满电结论；满足初始化窗口后给出暂定估值。不能无限等待稳定 |
| 正在充电 | 外电已确认、CHG_STAT 有效且去抖为充电 | 使用估值，未通过满电判据时最高 99%；不按充电时间自动加百分比 |
| 停充后稳定观察 | 已确认外电仍在，充电状态从有效变为非充电 | 保留历史用于判断电压回落；当前估值标为暂定。持续下降仍允许更新，不能全程保持原高值 |
| 外电待机 / 满充未确认 | 外电仍在、非充电，但没有足够满电证据，或稳定观察超时 | 按稳定电压提供参考估值；不能标为已充满，不能把它称为正在放电 |
| 估计满电 | 通过下节多条件判据 | 允许显示 100%；仍持续核验电压与输入状态，并有明确撤销条件 |
| 电池运行 | 可靠读数确认外电移除 | 电压滤波重新预热，沿用旧显示仅作过渡参考；稳定后使用相应放电工况曲线，不继承充电端高电压作为放电基准 |
| 测量未知 | 读数无效或过期 | 显示 `--%`，满电证据立即失效；恢复后重新建立有效窗口 |

“估计满电”属于软件证据状态，不是测得的实际容量。运行工况变化后不能无条件将百分比强制为只增或只减。

暂定估值可在电池数字前加 `~`，如 `~90%`；可信度仅表达“参考模型/过渡状态/本机已验证工况”，不伪造一个 0–100% 的概率。现有电池绘制区域有固定字宽，实施时验证 `~99%`、`100%`、`LOW` 和未知态的尺寸。

## 三、满电判据：多条件成立才允许 100%

下面是**待日志回放与实机验证的初始工程参数**，不是已经测得的电芯参数，也不是充电芯片的调节值。所有参数集中定义，随模型版本记录。它们用于防止过早显示满电，不能证明电芯健康。

| 参数 | 初始方案 | 依据与限制 |
| --- | --- | --- |
| 数据过期 | 5 秒 | 沿用当前规则；数据空档不计入连续成立时间 |
| CHG_STAT 去抖 | 2 秒 | 沿用当前规则，同时保留原始状态供核验 |
| 开机初始化窗口 | 至少 30 秒，通常不超过 120 秒 | 过滤当前只有数秒的高压启动段；超时后若数据有效，显示暂定估值，不无限保持未知 |
| 稳定观察窗口 | 120 秒 | 计算窗口内中值电压的 P95−P5 和趋势；不是声明电池已达到电化学静置条件 |
| 暂定稳定条件 | P95−P5 ≤20mV，趋势绝对值 ≤5mV/分钟 | 候选条件，需回放确认能区别噪声与本机持续回落 |
| 高压候选 | 中值电压 ≥4170mV 持续 180 秒 | 接近现有参考表 4177mV 满电端点；本次不到十秒的高压段不能通过 |
| 充电历史 | 同次启动中曾连续有效充电 ≥60 秒 | 作为充电结束路径的证据之一，不等同于测得净充电电流 |
| 停充资格 | 外电稳定、连续非充电 ≥120 秒，稳定窗口低端 ≥4150mV，并满足稳定条件 | 仅“非充电”不能认定满电；高压候选和充电历史还须有效 |
| 无充电历史的高压启动 | 外电稳定、非充电且中值 ≥4170mV 稳定至少 5 分钟 | 处理设备关机时完成充电的情况；仍只是估计满电。快速回落的本次轨迹不能通过 |
| 满电撤销 | 中值电压 <4100mV 持续 30 秒，或传感数据过期 | 清除满电状态，进入稳定观察/未知状态；低压判断无需等待这 30 秒 |

正常充电结束路径要求“充电历史、高压候选、有效停充和稳定条件”全部成立，且属于同次持续外电会话；短暂补电脉冲、短暂峰值、重启前未核实的状态不能拼成满电证据。

无充电历史路径用于关机充电后的启动，需独立通过更长的高压稳定观察，不能凭用户看到一次 100% 自动认定。本阶段没有外部电压基准，若上述电压条件一直不成立，应继续报告估值而非降低门槛迁就当前平台。

拔电后立即退出“外电估计满电”状态，进入电池运行过渡；持续充电或补电不意味着一直保有满电资格，仍受电压撤销条件约束。第一版满电证据只保存在 RAM，新 boot 重新确认，避免把关机期间未知变化当成已知。

## 四、百分比更新规则

1. 初始化窗口内不把 4190mV 的一次峰值显示为确定满电。有效低压提示仍可优先出现；初始化不能阻止低压判断。
2. 非满电状态下，电压估值最高显示 99%。只在满足满电判据时显示 100%，并在遥测中说明成立原因。
3. 对充停、拔插电和工况变化引起的短时扰动，使用有截止时间的稳定观察。有效观察超时后按当前电压估值显示，不把高百分比无限保留。
4. 平稳阶段沿用电压滤波和约 2 个百分点的显示滞回。第一版不恢复此前曾造成低电滞后的全程慢速百分比爬坡，也不在接 USB 时强制“只增不减”。
5. 显示大幅修正时记录 `reason`，如初始化完成、稳定观察结束、持续电压下降、满电资格撤销或模型切换，便于区分估值校正与实际放电。

对本次轨迹，第一阶段的正确结果是：不因数秒高压宣告满电；进入参考估值/稳定观察；4.09V 继续降至约 4.04V 时仍反映下降。不能将“改版后一直保持 100%”作为验收标准。

## 五、本机标定：第二阶段单独进行

### 不增加仪表时

记录受控工况下的可用运行周期：先建立尽可能可信的充电起点，固定无线方式、亮度、CPU/音频工作模式，再记录到既定软件低电终点；训练周期与验证周期分开。不能拿当前一段不完整日志生成全曲线。

优先覆盖两个常见工况：BLE 静置息屏，以及 BLE 正常亮屏。第一轮应固定一种工况跑完整周期，不使用“每分钟亮暗交替、把全程时间都算成两种负载各自容量”的方法；不同工况应分别记录或用经过验证的联合模型。

该条件下，时间比例只能标定“相应工况的可用续航比例”，不能声称测得 mAh 或绝对 SOC。若自动省电、动作、传音、断连或提前关机破坏工况，需把影响记录清楚，必要时该周期只作为观察数据。没有可信起点就不启用新表。

### 需要容量精度时

由台架/售后独立核对 VBAT、内部充电供电和电池侧电流；以电流积分形成真实容量基准，再拟合本机曲线，或评估专用电量计。这一步用于解决现有传感器信息不足，不能由显示状态机替代。

标定数据包含设备 chip、固件/模型版本、工况、起终点方法、训练/验证记录。先对 `6046e5b1e87c` 生效，另一台设备继续用参考模型。新表须保持电压和百分比单调、端点合理；未覆盖工况回到参考估计，不能直接借用其他电芯的表。

旧 `BatteryCalibration` 当前因此前取消物理标定而禁用；其“非充电且电压≥3300mV稳定三分钟就 Ready”的条件不能作为本方案满充资格。若后续实施标定流程，应先替换这个判据。当前用户请求是设计方案，不启动放电测试。

若后续实现涉及 Mac 重新构建，遵守本仓库要求，使用 `scripts/build-macos.sh` 安装并从 `/Applications/ThinCube.app` 联调。本方案阶段不进行构建安装。

## 七、验证与实施顺序

**第一阶段：测量记录与状态管理。** 先增加可选遥测、纯策略模块及真实日志回放，在主机验证后编译固件。实机在原配对和设置保留的条件下观察正常接电、关机充电后启动、拔电和重新插入，不自动安排长时间放电。

至少覆盖以下有区分力的场景：

- 本次 4192→4090→约4040mV 轨迹：不获得满电资格，稳定观察不无限保持高值，持续下降仍可见。
- 合成持续高压充电→稳定停充轨迹：资格完成前≤99%，符合全部条件后才为100%；短时峰值和短时充停均不误认满电。
- 已估计满电后持续下降：按撤销条件退出100%，外电仍在也不锁死。
- 传感失败、五秒数据过期、断连后的日志空档、供电未知、新boot、时间计数回绕：不能跨空档累计资格或恢复旧满电状态。
- 拔电后负载压降与低电：展示过渡不能推迟低压提示，不能放宽OTA门槛；不能用“显示暂定”跳过低电判断。
- Mac新旧固件数据、重复/倒序样本、日志容量及UI更新：可选字段兼容，记录和显示一致。

**第二阶段：本机标定与独立周期验证。** 只有完成可信起终点与工况记录，才生成并启用新表。评价可用续航误差或真实容量误差时，明确采用哪一种基准；在没有真值前不许诺±5%之类精度。

软件完成标准：状态机通过上述行为验证，误报满电被消除，持续下降和低压仍可见，日志可解释每次大幅修正。完整准确度完成标准：模型在独立周期和目标工况下通过事先约定的误差验证。第一阶段不能被描述为已修复全部充电/电池问题。
