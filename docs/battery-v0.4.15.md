# v0.4.15 电量跟踪修复与放电诊断

日期：2026-10-13。设备 v0.4.15，Mac 0.4.8（build 29）。针对“屏幕还有六七成电，约十分钟后无法开机，接 USB 才能恢复”的反馈，先修复已经复现的软件问题，并准备后续纯电池诊断。前期证据见 [排查报告](battery-investigation-2026-10-13.md)。

## 本次实现

- 保留每秒采样、7 点中值和 1/8 EMA，移除滤波后的“每五秒只变一个百分点”限速，以及低于 10% 时直接跳转的特殊分支。显示直接跟踪滤波结果，保留两个百分点的迟滞和 0/100 边界，避免数分钟维持高读数。
- 外部供电与电池供电之间切换时丢弃旧滤波窗口，经过五个新有效样本重新估计；未知供电读数不会冒充拔线。预热和长期读取失败继续显示 `--%`。
- 百分比增加 `~`，明确它是电压估计。纯电池供电时，原始电压与中值连续三次不高于 3420mV，显示红色 `LOW`；恢复需两者连续三次达到 3500mV。确认从已有稳定高电压突降的低压警告约需六个低样本；这组数值是软件提醒阈值，不是电芯容量标定或硬件保护配置。
- 充电 GPIO 读数增加新鲜度检查，失效超过五秒后不再显示旧充电态。OTA 保留原始、中值和滤波估计的保守最低值，未知/预热期间继续拒绝升级。
- 增加只读 USB `power` 命令，输出 PM1 版本、低压阈值、休眠配置、复位原因及当前电源状态；启动也记录配置。不修改 PM1 保护阈值。
- Wi-Fi 完整状态及 BLE 快速状态增加可选 `power` 遥测，约一秒一个新样本，BLE 传音期间继续传递。完整状态容量调整为 2048 字节，与既有 BLE 分片上限一致；具体字段见 [协议](thincube-protocol-v1.md#v0415-电源诊断扩展)。
- Mac 在后台写入本地电源日志，按设备、启动标识和 MCU 采样时间去重；重复和同次启动的倒序快照不刷屏，支持毫秒计时回绕。日志带电压、供电、显示、亮度、传音/音效和无线方式，无音频内容、PIN、密钥或会话 cookie。

日志位置：`~/Library/Application Support/ThinCube/power.jsonl`。单文件最多 2 MiB，保留当前和 `power.previous.jsonl` 两份。日志依赖已完成应用配对的无线连接；客户端断连本身不等于低电关机。

日志解释边界：`brightness` 是应用配置亮度，不是睡眠调光后的即时 LCD 背光；`failures` 仅统计 VBAT 读取失败。当前无线快照未包含空闲计时或关机原因，不能仅凭断连事件认定触发了哪一种关机。

本轮没有替换未经本机标定的电压—容量曲线，没有修改十分钟空闲关机策略，也没有通过降低欠压保护来延长运行。

## 已完成验证

1. 17 个固件 C++ 测试程序全部通过，电量测试从 9 组扩展为 15 组。增加持续电压变化后 30 秒内距电压估计不超过五个百分点、低压提前告警、尖峰过滤、供电切换重新预热、失效/恢复和计时回绕。该五个百分点是跟踪误差，不代表真实容量精度。
2. Swift 74 项测试零失败；新增电源样本解码、去重、倒序、回绕与 BLE 增量兼容验证。完整套件中的实际镜像识别因环境变量未设而跳过，随后指定 v0.4.15 镜像单独执行该项。
3. 固件 release 构建成功：静态 RAM 104776 字节，Flash 1707681 字节；应用镜像 1708112 字节，SHA-256 `e3fbd1e9eaa6936120dfd2ed794ddac62814309cab3d99f805429fd34742fd31`。
4. 更新前完整备份 8MB Flash，SHA-256 `2814c0139a307d05fcfbe649a284a66108e78557eb1fbb8d98a5fbbac4e3578d`。解析实际分区和两份 OTA 数据并校验 CRC，确认活动 app1 位于 `0x210000`，旧版本 v0.4.14；只写该应用槽，写入哈希校验通过，NVS、分区表、OTA 数据和 app0 未写入。
5. USB 真机正常从 app1 启动 v0.4.15，观察至 85 秒，IMU 和音频健康检查正常。采到 18 行电源日志：VBAT 3972–4026mV，I2C 电压读取失败计数为零；USB 供电下 `source=1 / auto_off=0`。PM1 实际 `BATT_LVP=64`，对应约 2500mV；`I2C_CFG=0`，空闲休眠关闭。只读回，未修改。
6. 实际 LCD framebuffer 截图确认 `~86%`、绿色填充、充电闪电和连接图标完整显示。低电红色 `LOW` 尚未通过实际欠压触发；判定逻辑已由 CPU 回放验证。
7. Mac release 构建、固定 Apple 签名与安装校验通过，已替换 `/Applications/ThinCube.app`，旧应用由安装脚本保存到 `artifacts/install-backups/`。
8. 用户完成正常配对后，BLE 电源日志持续落盘。2026-10-13 21:37 的十秒传音测试完成，传音期间收到 11 个新电源样本，跨度 9.87 秒，最大间隔 1.14 秒；VBAT 4012–4054mV，读取失败计数为零。截取的前后共 21 个样本无重复，USB 供电状态正确。该测试验证传音期间的遥测更新，未测电池放电容量。

### 持续亮屏的后续检查

观察期间没有出现五分钟熄屏或十分钟关机，故没有把断连误作耗尽；实际上此次未断连。为核对空闲计时，用户重新接入 USB。打开原生 USB 串口触发 `USB_UART_CHIP_RESET`，随后应用正常启动；这属于调试副作用，重启前的活动计时与阻塞条件未保留。

重启后的日志显示计时正常增长，约 30 秒进入视觉睡眠，实际背光降至 12，ES8311 关闭成功。空闲计时持续达到 234 秒；启动后约 240 秒，传感器姿态由约 `(-0.03, -0.31, 0.95)g` 变为 `(-0.06, -0.01, 1.00)g`，记录 `awake (motion)` 和一次拿起事件，计时归零，随后再次正常入睡。用户确认约 22:01 确实移动过设备，与此事件对应。

这次重置是符合设计的实际运动唤醒，不据此修改运动阈值。由于中途移动，本轮未完成连续五分钟完全不活动的熄屏验收；此前 v0.4.9 的 USB 验证见 [待机记录](idle-power-v0.4.9.md)。纯电池观察期间持续亮屏的具体触发历史仍未保存，不能把这次已确认的移动倒推为前段所有亮屏的原因。

## 尚未确认的范围

显示跟踪、供电切换与无线采样已通过本次实机验证，真实容量和接近耗尽时的行为仍未确认。电源键无法启动、插 USB 恢复仍需用覆盖故障时刻的纯电池记录区分欠压、电池容量/内阻及供电路径问题；不能把本次显示修复称为续航修复。下一步容量标定需确认充电完成、固定典型负载，并单独区分空闲关机；若复现突然断电，应结合断电前 VBAT 与不接 USB 能否开机，必要时测量电池端电压/电流。
