## 诊断测试

保持正常竖放并停止传音，长按 A 约 1.2 秒进入原诊断页。短按 A 依次播放 1–13 段；第十三段后下一次短按回到第一段。片段结束返回原 IMU/事件诊断页；播放中短按可换到下一段，长按 A 退出诊断。诊断页底部沿用 `A:story` 提示并显示下一段编号；演出时的 `DEMO` 编号按文本宽度靠右对齐，兼容两位编号。

诊断预览保持清醒，绕过自动等待与次数，但保留传音、流程、方向和电量等安全限制。USB 满电时，真实供电来源未变的充电指示切换不再误取消定向预览；真实供电变化、读数失效或低电量仍打断。自动小剧场继续在充电状态变化时取消。看完后长按 A 退出，才恢复日常低频调度。

USB `story 1` 至 `story 13` 与诊断播放共用入口，`story stop` 退出。原 `story 1..5` 编号不变；非法或超出范围的编号不启动片段。`scripts/demo-clawd-stories.py` 默认逐段检查十三段，旧固件可使用 `--version v0.4.12 --count 5`。

## 构建与验证

17 个固件 C++11 测试程序通过，无新增编译警告。调度检查扩展到十二组：覆盖十三段候选、A 键循环及 USB 编号解析、预览中连续换片、类别比例与情境权重隔离、预算/冷却/休眠/电量/计时回绕。十小时模拟与 20,000 次确定性选片继续通过；类别为八段日常、五段奇遇，所有片段均能被选中。

实际固件绘制代码采样 4,133 帧，检查角色区域裁剪、可见内容与首尾默认姿态逐像素恢复。原五段全部 1,565 个采样画面与 v0.4.12 源码快照逐像素一致；新增八段关键镜头已按原生像素复核。

release 构建静态 RAM 103,200 字节，Flash 1,705,357 字节；应用镜像 1,705,792 字节，SHA-256 为 `814089e06214d494bbc31aec964bafc198aa3f8b2916429884dbf0cfc03528b9`，符合既有设备身份、v1 协议与 2 MiB 应用分区。

更新前完整 8 MiB Flash 已备份，活动 app1 与 v0.4.12 镜像清单匹配。USB 仅写 app1（0x210000），写入 hash 校验通过；NVS、OTA 数据、分区表和 app0 未写入。该镜像沿用此前已经在设备运行的 EXT_5V 降噪和三级待机优化，相关源码与验证说明保留在同一提交中；本次未重建上位机。

最终镜像的十三段均通过共享 USB 诊断入口完成实机定向播放，取得十三张原生 135×240 LCD 关键帧；片段结束恢复原诊断页，停止预览后恢复正常主页，画面确认 Mac 在线。满电充电指示切换未再取消预览，定向播放未消耗自动预算。最大绘制耗时 21,916 μs，低于原 33 ms 间隔；退出后继续观察至启动 65 秒，无运行中重启、音频队列丢帧为 0，公共设备信息确认 v0.4.13、Wi-Fi 和 paired=true。

上述结果来自同一最终镜像的两次 USB 会话：第一次完整验证 1–9 段，截图验收脚本在第十段等待结束时超时；为 USB 导出与采集恢复留出余量后，将脚本结束等待由 5 秒调整为 8 秒，第二次完整验证 10–13 段及恢复页面。期间固件镜像未再更改。实机结果与验证边界记录在 `artifacts/clawd-stories-v0.4.13/validation.json`。自然首播、小时预算与冷却通过时间模拟检查；不以 USB 演示代替物理 A 键观感验收，也不将定向播放描述为长期音频压力测试。
