# 5/10/20 分钟深睡策略：固件 v0.4.58 / Mac v0.4.30

日期：2026-10-20，Asia/Shanghai。

开启「深睡待机」后，三个时间点都从最后一次真实活动起算：

| 持续静置时间 | 状态 | 恢复方式 |
|---|---|---|
| 5 分钟 | 在线息屏，保持当前连接 | 沿用现有运动、按键及 Mac 手动语音唤醒 |
| 10 分钟 | 纯电池供电下进入 PM1 L1 深睡，主控断电，保留 IMU 运动唤醒 | 拿起或按机身电源键，重新启动并自动认证重连；A/B 与 Mac 指令不能唤醒 |
| 20 分钟 | 解除运动唤醒与 IMU 保电，再完全关机 | 机身电源键开机 |

提前活动或唤醒会取消旧期限，重新获得完整的 5/10/20 分钟窗口。心跳、睡眠确认、角色动画和周围声音不刷新计时。传音、游戏、配对、配网、OTA、模式切换、旋转、诊断、组合手势及失效运动输入继续采用原有保护条件；受保护任务结束后重新计时。

USB 供电时仍可在线息屏，不自动深睡或关机。关闭深睡开关时维持原五分钟在线息屏、十分钟纯电池完全关机。深睡暂不可用时，已开启的策略仍在二十分钟执行在线关机，不在十分钟提前关机。

## 主控断电后的关机

深睡切断 ESP 供电，无法继续运行 `millis()` 或 ESP RTC 定时任务。入睡前通过 PM1 独立定时器安排一次 `ARM|POWERON`，剩余秒数为 `(DeepOffMs - 当前空闲毫秒数)` 向上取整，包含睡前通知、确认及外设准备耗时。正常十分钟入睡后再计约十分钟；延迟入睡仍以原二十分钟为期限。

PM1 的定时 `POWEROFF` 会遵守保电配置，无法自动解除 IMU HOLD 与 GPIO 运动唤醒。因此到期后短暂启动 ESP，在应用界面与无线服务启动前检查醒因和供电，清理保电配置，再完全断电。硬件以秒计时且有启动开销，实际断电会比二十分钟期限稍晚，尚未测量本机误差或屏幕上电瞬态。

依据：[M5PM1 数据手册](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1207/M5PM1_Datasheet_CN.pdf) 的系统定时器、GPIO_Power_Hold、GPIO_WAKE_EN 和 RTC RAM 定义；[官方驱动](https://github.com/m5stack/M5PM1/blob/main/src/M5PM1.cpp) 的 `timerSet` / `timerClear` 顺序。工程使用既有 M5Unified 的 checked I2C 接口，不增加驱动依赖。

PM1 RTC RAM `0xA0–0xA7` 保存版本化八字节标记，不写配对或校准 NVS。每次启动读取标记与醒因后清除定时器和标记。只有标记完整、醒因仅为定时器、即时确认纯电池、电源键未按下及运动中断线安静时才尝试到期关机；混合醒因、USB 或用户输入优先正常开机。关机前清除 GPIO4 运动唤醒及 IMU/GPIO4 HOLD，并再次读取供电和输入。

配置、读回、唤醒事务或断电失败时取消计时并恢复在线状态；准备取消或缺少睡眠确认后间隔三十秒重试，保留原真实活动时刻，不因此推迟二十分钟关机。未确认清理成功时禁用该次启动的深睡，并在正常循环中继续重试清理，防止 I2C 恢复后留下旧计时器。没有新增无唤醒源的 ESP 睡眠。准备拖过二十分钟时交回在线关机流程，不另开十分钟计时。
