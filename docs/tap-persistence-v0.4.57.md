# 敲击设置保存在设备：固件 v0.4.57 / Mac v0.4.29

用户调整日常档位、启用开关或高级参数后，点击「保存到设备」。设置在设备上保存，设备重启、休眠唤醒以及 Mac 重新连接后继续使用，不需要上位机重发配置。

「恢复推荐…」需要主动确认，然后由设备恢复推荐参数并保存，保留设备当前的启用开关。「清零识别计数」继续只清计数，不修改运行参数或已保存记录。未保存的草稿不写入设备。

## 存储与确认

完整配置保存在专用 NVS 命名空间 `thincube_tap` 的 `config` 键，使用 40 字节的固定格式：标识、格式版本、8 个布尔位、15 个小端数值及 CRC32。避免直接存储编译器结构体和填充字节；加载时检查版本、长度、校验与全部参数范围。记录不存在时采用推荐值；损坏或不可读取时保留原记录并暂停敲击检测，界面提示需要重试保存或主动恢复。

保存前先完整应用并读回传感器配置，之后提交 NVS，并重新读取完整记录核对。写入失败或提交结果不确定时尝试恢复之前的运行和存储配置，任何未确认的结果都不显示保存成功。相同记录避免重复写 Flash。重新上电时在启用识别前加载保存值，并同步稳定、按键抑制和冷却参数。

## 接口

HTTP 与 BLE 沿用认证后的 `api/tap` / `op=tap`，新增状态 `persistence=1`、`saved` 和 `storage`。`saved=true` 表示运行参数与已确认的存储记录一致；成功提示同时要求请求 ID、参数逐项一致、传感器读回成功和保存成功。

`action=configure` 保存完整配置；新增 `action=restore` 恢复推荐并保存；已有 `action=reset` 仍只清计数。旧上位机的配置写入也会持久保存；新上位机面对不支持持久保存的旧固件会明确提示升级，禁用保存，避免把临时应用误报为保存成功。设备恢复出厂仍按其既有全配置清理流程清除此命名空间。

## 验收

两个固件环境构建通过，42 个 C++ 回归程序、Bosch SDK sanitizer、Python 回归和 Swift 107 项（1 项已有跳过）无失败。新增存储测试覆盖全部字段序列化、每一位损坏、版本/长度/范围错误、不重复写入、提交结果不确定、存储读回失败及运行/存储回滚。

ThinCube-6046E5（`7c:e8:b1:e5:46:60`）安装前保存原敲击参数并完整备份 8 MiB Flash，仅更新活动 app0 到 v0.4.57。写入后在首次启动前逐字节核对，应用槽之外全部 Flash（含配对、校准、NVS、分区表和 OTA 元数据）未变。升级后将原用户敲击配置保存到设备，Mac v0.4.29 build 50 已实际安装至 `/Applications/ThinCube.app`。

上位机实际保存「用力／稍慢／加强」和关闭开关，硬件重启后 USB 独立逐项读回完全一致，启动日志直接报告从存储加载；清零计数与取消恢复推荐后均保持自定义设置。确认恢复推荐后再次重启，推荐参数保留且开关仍为关闭。最后重新保存升级前的原配置，第三次重启后逐项核对完全一致、传感器健康且错误为零。5 项快捷键配置哈希保持不变。最终窗口显示「已读取设备保存的设置」「已保存到设备 · 重启后保留」。记录在 `artifacts/persistent-tap-v0.4.57/`；本次没有追加物理敲击准确率采样。
