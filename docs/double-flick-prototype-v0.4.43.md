# 手持连续双甩诊断原型 v0.4.43

2026-10-18。双敲在正面 A 键上方的体验未通过，转为软件六轴双甩诊断；用户要求连续甩两下才触发。当前阶段只验证动作和误触，不发送上位机快捷键。

## 动作定义

保持正常对讲握姿，用手腕连续甩两下，最后停稳。首甩方向不限，第二次强脉冲与首次方向相近。diag3 不要求两下之间先回到静止握姿，不按预备小动作锁定单轴；两次之间需有反向制动，第二次之后也需收回。只甩一次不会触发。

采用已有 Legacy 后端的加速度和陀螺仪采样，不迁移 Base 腕部识别、不启用 Legacy tap。姿态、A/B、传音及休眠唤醒路径沿用。识别器运行在主循环，只读取采样快照，不改 IMU 配置，也不写入用户设置。

## diag3 参数

| 条件 | 初值 |
| --- | --- |
| 允许场景 | 已连接、未静音、正在对讲、A/B 均松开 |
| 排除场景 | OTA、配网/配对、切换信道、休眠、电量校准、横屏游戏 |
| 起始停稳 | 350 ms，角速度合量低于 45°/s，重力模长偏差小于 0.2 g |
| 候选起点 | 角速度合量达到 300°/s |
| 每次强脉冲 | 至少 500°/s，至少两个样本；第二次沿首次方向的正向面积至少 8° |
| 首次方向 | 前 220 ms 内最强角速度向量，不按预备动作锁轴 |
| 两次方向关系 | 向量相似度至少 0.65 |
| 反向制动 | 沿首次方向投影低于 −150°/s，两次之间及第二次之后均需要 |
| 首次主峰至第二次强脉冲起点间隔 | 180–900 ms |
| 最后回姿 | 停稳时重力方向与开始方向点积至少 0.85；单轴积分仅作诊断，不用来证明姿态回归 |
| 整组双甩窗口 | 从首次候选开始 1600 ms，含最终停稳 |
| 最终停稳 | 100 ms |
| 触发后冷却 | 至少 1200 ms，且重新停稳 350 ms |
| 采样间断 | 大于 80 ms 取消候选，避免跨空洞积分 |

按键按下、离开对讲或传感器不健康会清除整组候选。首次强脉冲确认只打印 `flick-first`；两次强脉冲、反向制动及最终回姿停稳均满足才打印一次 `flick-event`。第三次同向强脉冲若在最终停稳前出现，会取消这一组。两次同形的日常动作仍可能与有意双甩重合，需用真实负样本验证，不能仅凭窗口和单元测试宣布无误触。

## 构建与诊断

```sh
pio run -d firmware -e m5stack-sticks3-flick-diag
python3 scripts/diagnose-flick.py --output-dir artifacts/flick-diagnostic-v0.4.43
```

独立环境标记 `THINCUBE_IMU_LEGACY`、`THINCUBE_FLICK_DIAG`，当前构建版本 `v0.4.43-flick-diag3`。默认 Base 环境及原双敲诊断环境保留。单独编译的 Base/双敲版本默认关闭软件双甩。

USB 命令：`flick status/on/off/reset/trace/trace off`。diag2 的 `trace` 输出最长 60 秒、最高 100 Hz 的新六轴快照，实际频率受主循环限制；识别使用每个新陀螺仪样本，不以日志频率运行。初版 trace 为 20 秒/25 Hz。`flick-status` 展示场景是否允许、传感器健康及计数。所有命中、拒绝日志均标记 `diagnostic_only=1`。`tap sleepcheck` 仅测试休眠准备和撤销，不断电。

采集脚本保持同一 USB 连接，避免反复开串口重启。使用 `begin LABEL` 划定动作段，`end N` 保存本段事件及操作者报告的动作组数。未逐次标注的批量组数不能直接当成精确识别率。需要先确认设备处于正常对讲握姿，再开始采集。

这是小样本可行性验证，不能据此宣称总体 100% 识别或无误触。进入快捷键阶段前，追加至少 25 组逐次标注双甩（累计至少 30 组），覆盖轻/正常力度和自然方向；扩展走动、换握、拾放、持续摇晃、A/B 操作的负样本，并复核控制心跳偶发超时与实际休眠唤醒。期间先冻结 diag3 参数，区分无效会话、算法拒绝、漏报与重复报告。

## 手持验证顺序

先做 5 组自然双甩，每组间隔至少 3 秒，检查原始角速度、主轴和拒绝原因，再决定是否调整初值。随后逐次标注至少 30 组，区分漏报和一组多报；负样本单独覆盖单甩、换握、拾放、走动、转身、持续摇晃、A/B 操作。完成后复核姿态退出、传音、按键与休眠唤醒。识别及误触验收通过后，另接事件协议与上位机快捷键，双甩应映射为离散动作。
